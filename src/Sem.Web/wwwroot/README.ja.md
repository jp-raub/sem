# SEM — Session Room UIモック

[英語版（正本）](README.md)

最新のアカウント方式の設計に基づく、バックエンド不要の静的モックです。本番Blazor Serverとは別の画面検討用試作です。既存のルートREADMEとmainは変更していません。

## GitHub上で試す

`ui/session-room-mock` ブランチを開き、Code → Codespaces → Create codespace on this branchを選択します。ターミナルで、リポジトリのルートから次を実行してください。

```sh
python3 -m http.server 8000 --bind 0.0.0.0 --directory mock
```

Portsパネルのポート8000をブラウザで開きます。公開範囲は **Private** のままで確認できます。ビルド・アプリ用パッケージ導入は不要です。同じコマンドでローカル確認も可能です。GitHubのソース表示画面ではHTMLは実行されません。

## GitHub Pages（任意・未公開）

`.github/workflows/ui-mock-pages.yml` はHTML/CSS/JSだけを `ui-mock/` 配下に配置して公開する手動実行ワークフローです。pushによる自動公開はありません。PRを確認してmainへマージ後、Settings → Pages → SourceをGitHub Actionsに設定し、Actionsの Deploy UI mock to Pages を手動実行します。実行結果のURLは `/ui-mock/` を指します。

非公開リポジトリをPagesのために公開へ変更しないでください。利用可否はGitHubプランに依存し、リポジトリが非公開でもサイトは公開の場合があります。公開範囲を確認してから利用してください。このワークフローはモックだけを公開します。将来別のPagesサイトがある場合はその内容を置き換えるため、事前確認が必要です。Codespaces・ローカル確認ならPagesも一般公開も不要です。

## デモアカウント

| 種別 | メール | パスコード | 範囲 |
|---|---|---|---|
| 参加者 | member@example.test | demo | 表示可能なイベント・自己登録・コメント |
| イベント管理者 | event@example.test | demo | 秋イベント限定。サービス管理は不可 |
| 全体管理者 | admin@example.test | demo | 全イベント・ユーザー・招待管理。特権ロール解除不可 |

ログインのショートカットとヘッダーのユーザー切替で各ロールを試せます。招待コード `SESSION-DEMO` は2030年まで有効・複数回利用可。`#/register?invite=SESSION-DEMO` で自動入力、クエリなしでも登録フォームを表示します。ログイン画面に自由登録リンクはありません。

## 制約・注意

- 認証・権限は画面上の模擬動作で、ユーザー切替で回避できます。実際のメール・パスコード・トークン・参加者情報は入力しないでください。パスコードは保存せず、再ログインは全員 demo です。
- データはlocalStorage、ログイン状態はsessionStorage。実DB/API/ユーザー間同期/排他制御/SignalR/メール/リセットリンク/スケジューラ/バックアップ/PostgreSQLはありません。
- 自動切替は選択日時のボタン評価です。再評価で手動上書きを解除します。本番のスケジューラ・上書きの扱い・登録時フェーズ保存は実装が必要です。
- 上限を超えた候補も選べますが送信時に上限適用・超過枠を個別エラー表示します。選択時のガイドは改善対象です。
- パートマスタ管理・既存曲の情報編集は未実装。追加時はカンマ区切りのパート名を使います。本番はPartDefinitionsを参照します。イベント/ユーザー削除は要求どおりありません。
- JavaScriptのデータは試作用で、最終DBスキーマではありません。Blazor/EF Core構成は変更しません。
- file:// の保存挙動には差があるためHTTPで起動してください。
