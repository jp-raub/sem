# UI mock v4: 日時書式・イベント別演奏パート

## 日時

日時の表示・編集はyyyy/MM/dd HH:mmに統一。開催日時、概要編集、フェーズの期間・評価日時、招待発行日時・期限、コメント・監査時刻が対象。端末ごとの標準日時入力書式を避け、編集は固定書式のテキスト入力。存在しない日付や時刻を拒否。表示は日本時間。内部保存は従来互換のISO形式。タイムテーブルの時刻とm:ss / h:mm:ssの所要時間入力は変更しない。

## サービスプリセット

全体管理者がサービス管理の編集モードで、新規イベント用のパート名・Sing/Play分類・順序を追加／編集／削除できる。初期値はVo、ChoがSing、Gt、Ba、Dr、KeyがPlay。保存は最後に「変更を保存」。既存イベントには自動反映しない。

## イベント別定義

新規イベント作成時にプリセットをコピー。作成画面で不要なパートをOFF、不足するパートを追加できる。作成後は全体管理者・対象イベント管理者がイベントの編集モードで調整可能。曲のトグルとCSVはイベント内の定義だけを使用。

イベント定義のIdを曲枠のPartDefinitionIdに関連付ける。名称変更は同じIdの曲枠にも反映し、担当者と枠Idは維持。曲で使用中の定義は削除・分類変更を拒否。曲側の使用を解消した後に変更する。未使用の定義は削除可。プリセットと各イベント定義は独立。

既存イベントは現在の曲パートを保持してイベント定義へ移行。旧Vo/ChoはSing、その他はPlayを初期分類とする。担当者の自動解除・既存内容の削除は行わない。パート名は安全な1〜40文字、区切り記号 | とHTML特殊文字等は不可。

## 兼務

名前ではなく分類で判定。1パート、またはSing 1つ＋Play 1つだけ通常登録可能。Sing同士・Play同士・3つ以上は不可。フェーズをまたいだ既存枠も含める。管理者の理由付き例外は維持。
