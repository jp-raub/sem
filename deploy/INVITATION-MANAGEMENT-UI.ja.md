# 招待管理UI

## 対象範囲とアクセス制御

`/invitations` は認証必須の画面で、静的prerenderを無効にしたInteractive UIです。ナビゲーションリンクはページ全体を再読み込みし、訪問ごとにJavaScriptモジュールを初期化します。ログインユーザーにAPIが返す招待・依頼だけを表示します。管理者は目的・利用上限・有効日数の明示確認を伴う招待の直接発行と、理由・明示確認を伴う既存招待の失効ができます。発行リンクは成功応答後に一時的な読み取り専用欄にのみ表示し、コピーは明示クリックで行います。権限の最終判断は常にサーバー側で行います。

依頼作成・承認と自動リンク配布は未統合です。秘密リンクをアンカー、一覧行、クエリ、ブラウザー保存領域、ログへ入れません。APIにない過去の目的・発行元情報を推測せず、null値は「未記録」と表示します。一覧が全件を含むとは表示しません。招待・依頼を別々に最大50件取得し、両方に同じページ番号を使います。APIのページ番号上限は10000です。`hasMoreInvitations` または `hasMoreRequests` のいずれかが真で、かつ現在ページが10000未満の場合に次ページへ進めます。10000ページ目でいずれかが真なら次ページ操作を無効にし、API上限の先に未取得データが残ることを明示します。

発行endpoint、確認、リンクの取り扱い、結果不明時の制約は [招待直接発行UI](INVITATION-ISSUANCE-UI.ja.md) を参照してください。

## 読み取り専用一覧

`GET /api/core/invitations?page=N` を呼び出します（初回は明示的にpage 1を要求し、要求ページは1～10000に限定）。レスポンスのactor、`pageSize: 50`、2つの `hasMore` フラグ、各配列の件数を検証します。10000ページ目で `hasMore` が真ならNextを無効化し、API上限を表示します。page 10001は要求せず、残りの記録を取得済みとは表示しません。日時はUnix秒として受け取り、日本標準時で表示します。表示名が未設定または空なら `不明` と表示します。一覧行にはAPI契約にあるID、名前、目的・発行元（nullable）、件数、日時、状態、保存済みの理由だけを表示し、null値は「未記録」とします。行にはメール値、トークン、招待リンクを表示しません。

すべてのAPI要求はsame-originのcredentials/mode、`redirect: "error"`、`cache: "no-store"`、25秒の中断上限、fatal UTF-8 JSON解析を使用します。バイト上限は一覧応答512KiB、CSRF応答16KiB、変更応答4KiB、JSONリクエスト本文4KiBです。解析前にバイト数を検査します。一覧応答が上限超過または不正形式の場合、部分データを解析・適用せず、安全なエラーを表示して、正常な明示再読込まで行操作をロックします。変更応答の上限超過・形式不正は結果不明として扱い、自動再送しません。

## 管理者による失効

次の形式で送信します。

`POST /api/core/invitations/revoke?expectedActor=<actorIdと完全一致>`

```json
{"id":"…","reason":"…","explicitlyConfirmed":true}
```

理由は前後の空白を除いて1～500文字で、制御文字を含められません。IDは1～128文字で、制御文字を含められません。選択した行は確認画面へsnapshotとして保持します。理由が変更されたらcheckboxを解除し、別行の選択や一覧の再読込でも以前の確認を破棄します。CSRFトークンは `GET /api/csrf` から取得し、`X-CSRF-TOKEN` で送信します。失効後の一覧情報はサーバーが返す値だけを表示し、変更応答から失効日時や実行者を捏造しません。

明示確認した場合だけ変更を送信します。401/403ではactorに紐づく状態を破棄します。タイムアウト、通信断、不正・上限超過応答など結果不明の場合は管理者操作をロックし、自動再送しません。読み取り専用の一覧再読込で対象IDを確認してください。行があればサーバー由来の `disabled` 状態で照合し、見つからない場合は該当ページを手動で探して確認するまでロックを維持します。既に無効な招待に対する冪等処理と元の理由の保持はバックエンド契約に従います。

## 表示と検証

APIの名前、理由、IDなどの文字列はDOM要素を作成して `textContent` で挿入し、raw HTMLとして扱いません。発行した秘密リンクは表示中ページの一時的な読み取り専用input valueにのみ保持し、ブラウザー保存領域、現在のURL/query/fragment/history、ログへ書き込みません。コピーは明示操作です。モジュールはページowner/rootに紐づけ、破棄時にイベントリスナーを解除し、要求を中断します。generation検査により古い応答が後続画面を書き換えないようにします。

合成UIチェックは一覧のAPIページ上限と、招待・依頼それぞれ独立した `hasMore` 境界（10000ページ目でNext無効・上限表示）を含みます。実行コマンドは以下です。

```sh
node --check src/Sem.Web/wwwroot/invitation-management.js
node --check scripts/invitation-management-ui-checks.mjs
node scripts/invitation-management-ui-checks.mjs
```

合成テストでは一覧の容量上限、安全なテキスト表示、両collectionのページ境界、明示的な理由・確認、結果不明の照合を確認します。親統合側の.NETビルド、endpoint/CSRFテスト、ホスト・ブラウザー受入試験の代替にはなりません。
