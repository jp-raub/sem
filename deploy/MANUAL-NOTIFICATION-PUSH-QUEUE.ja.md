# 手動通知の端末別キュー（実送信は未接続）

## 範囲と安全境界

PR44に永続的な準備・所有者トークン・結果確定の部品を追加します。DI／HTTP／ワーカー登録、有効化更新、走査処理、外部送信の呼出しはありません。移行は `ManualNotificationPushPreparations` と `ManualNotificationPushDeliveries` の作成だけで、過去受付の展開や有効化をしません。確定宛先・ボックス／既読・宛先Pending・自動Push・SMTP・認証情報は維持します。

## 一回だけの端末準備

`PrepareAsync(recipientId)` は確定済み宛先だけを起点に、元の受付印・現在の有効化世代・受付＋600秒の期限・現在のアカウント／閲覧／参加を確認し、有効な現在端末だけを1トランザクションで一回取り込みます。宛先ID＋端末IDのハッシュを配信IDとし、組の一意索引も適用。保存するのは紐付けダイジェストだけで、エンドポイント／鍵／stamp／セッション／本文を複製しません。

拒否・有効端末なしも準備結果として永続化します。再準備は元の状態と件数を返すだけで、後発端末／参加者の追加や抑止済み通知の復活をしません。途中挿入失敗は準備記録・全端末行をロールバックします。端末削除で配信履歴を消さないよう端末への外部キーは付けず、占有前と送信前に現在の本人／紐付けを再確認します。準備後の端末追加を古い通知の新規配信とはしません。

## 占有と結果

- 期限到来済みPendingだけを、現在の方針・本人／紐付け・固定期限を同一トランザクションで確認して占有。同時要求は1所有者だけ。新トークン、期限以内の最大30秒リース、最大5試行。
- 占有だけでは送信不可。`RecheckAsync` は同じトークン・有効リース・全現在条件を要求し、拒否時は終端抑止／期限切れへ保存。再参加で復活しません。将来の送信はI/O直前に実行し、通信タイムアウト／TTLを残リース・期限以内へ制限する必要があります。
- 占有期限切れは**Unknown**で、自動Pending化しません。停止前に送信済みかもしれないためです。Unknownの自動再試行／照合APIはありません。
- ProviderAcceptedは配信基盤の受付時刻だけで、端末受信／既読ではありません。完了処理には現トークンが必要で、古い試行のトークンは後続試行・終端結果を上書きしません。同じ占有が維持されていれば遅れて届いた確定結果を記録できますが、別呼出しがUnknownへ切り替えた後の古い完了は拒否します。
- 明確な未受付を表すRetryableNotAcceptedだけが15／30／60／120秒の再試行を予定し、元の期限・最大5回を超えません。タイムアウト・応答喪失・曖昧な例外はAcceptanceUnknownへ分類する必要があります。SubscriptionGoneは終端で、生きている購読の削除はしません。PermanentFailureも終端です。
- 状態／理由はコードだけで、生の例外文や購読内容は保存しません。外部配信の完全な一回保証はせず、認可後からI/Oまでの競合は将来の送信側で最小化する必要があります。

## 検証

`dotnet run --project tests/Sem.ManualNotificationPushQueueChecks -c Release` は合成SQLiteで67項目を検証します。データ入り旧スキーマ／受付印の保持、既定OFF、一回の現在端末確定・後発非追加、同時準備／占有、所有者の区別、受付／不明／期限／購読失効／永久失敗、待機／回数上限、現在の参加／閲覧／セッション／紐付け／世代変更、ボックス保持、期限以内リース、2端末目挿入の故障注入時の全体ロールバック、実別プロセス再取得と合成結果確定、制約・整合性／外部キー・取消を含みます。実配信基盤・実機・Docker／DXP受入ではありません。

受付と直列化する監査付き有効化管理、上限付き走査／送信とタイムアウト・応答分類、定型Push／本人認証付きボックスURL、紐付けを守る失効購読処理、Service Worker／実機受入が残ります。配布・有効化・PRマージは別承認です。PR44文書は当初の境界の説明であり、本変更は承認済み方針を変えずにキューを拡張します。
