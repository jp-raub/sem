# 本人プロフィールの閲覧カードと明示編集

## 採用画面への対応

採用モック `9cf8b031258fa1c9afe9668f54e61f002c4bce17` のprofiles.jsと後続の履歴・アイコン・管理導線の上書きを基準にする。通常表示を本人の閲覧カード（画像／絵文字、読み、表示名、呼び名、SNS、プロフィール設問）と現在の参加登録履歴、QRの2列構成へ合わせる。760px以下ではQRを先に縦積みする。

`/profile/settings` と既知の旧アンカーを維持し、「プロフィールを編集」で中央のnative dialogを開く。名前・SNS・回答を既存の本人APIで保存し、成功確定後だけ閲覧カードへ反映して閉じる。取消／Escapeは未保存入力だけを破棄し、起動ボタンへ戻す。背景操作は暗黙に破棄しない。TabとShift+Tabは表示中・操作可能な項目の端で折り返す。狭い／短い画面は内部スクロールする。

## 独立した画像操作と結果不明

画像アップロード／削除は既存どおり**即時保存**で、名前等の一括保存とは別と明記する。画像更新後に最新の版番号を読み、編集途中の名前・SNS・回答は戻す。編集取消でも確定済み画像を巻き戻した表示にはしない。元画像をプレビューせず、既存の10 MiB入力・512px／1 MiB PNGへの正規化・画像専用版の境界を維持する。保留中のイベントヘッダー10 MiBとは別機能である。

通信中は取消／Escapeと重複保存を拒否する。プロフィールの書込み後に応答を確認できない場合や、保存済みだが最新表示を取得できない場合は、入力を保持し再保存と取消を止める。編集モーダル内の明示的な再取得で確定値を確認できる。画像の既存結果不明保護も維持する。競合は自動再送せず、APIの既存拒否と説明を保持する。

## 履歴とQR

- 登録履歴は既存 `profile-registration-history` を本人ID・現在の閲覧権限で取得する。新しい候補100件を選んでから認可を適用するため、全履歴とは表示しない。演奏／観覧を表示し、出席・演奏の実績証明とはしない。失敗時は古い一覧を消し、明示再取得できる。
- QRは初期読込や拡大で勝手に発行しない。既存の明示発行後にメモリへ保持する同じblob画像だけを拡大する。拡大は再発行・期限延長・新しい秘密URL取得を行わない。閉じると拡大画像を消し、起動ボタンへ戻す。既存24時間期限と公開DTO／共有範囲は変更しない。
- SNSはhttp/httpsかつユーザー情報を含まないリンクだけをtextContentで描画し、外部リンクのnoopener/noreferrerを維持する。名前・回答・履歴もHTMLとして解釈しない。
- 本人API、他者編集不可、世代／切断時のabort、401/403での個人表示消去、画像／JSONの容量制限、同一origin／no-store／redirect拒否を維持する。新API・DB・migration・公開範囲変更・モック認証・ダミーQRは追加しない。

## 自動検証と引渡し

既存のプロフィール／画像／履歴の合成検査と本人API回帰を維持する。新規DBの実ブラウザーで明示編集・保存・取消・正逆Tab・中央配置・明暗と狭幅、画像即時保存後の下書き保持、QR同一画像の拡大、通信中／結果不明の保護と再取得、旧プロフィール／アカウント遷移を確認する。full fixtureにも設定画面検査を接続し、危険な無効化を契約検査で拒否する。

公開候補の全ディレクトリ保全復元と40分／30分の必須CI枠は維持する。全UIの実装が揃うまで通常の個別承認依頼は出さず、全UI完成や物理端末の受入完了へは拡張しない。
