# Event import: public Google Spreadsheet CSV

## Behavior and scope

The existing event-import page can explicitly fetch a publicly accessible Google Spreadsheet as CSV and place the result into its existing CSV input. The fetch to Google is made directly by the browser and is a read-only source step: it does not preview or append anything. With this Interactive Server page, URL input events send the URL to the temporary Blazor Server circuit; the fetched CSV is transferred to that circuit using streamed JS interop (`IJSStreamReference`), not a single SignalR string message. These values are transient page/circuit working memory; they are not persisted to the database, browser storage, or application logs. When the manager explicitly runs preview or append, the CSV is sent to the existing app endpoints as required by that workflow. The manager must inspect the loaded text, run the existing preview, and separately confirm an append.

Only HTTPS URLs on the exact `docs.google.com` host are accepted, using spreadsheet edit/export URLs or published `pubhtml`/`pub` URLs. Regular sheets are normalized to `/spreadsheets/d/{id}/export?format=csv&gid={gid}`; published sheets are normalized to `/spreadsheets/d/e/{id}/pub?output=csv&gid={gid}`. A missing tab identifier defaults to `0`. A decimal `gid` up to `2147483647`, including one in a `#gid=...` fragment, is supported. Known `usp=sharing` and `usp=drive_link` decorations are discarded. Duplicate parameters, unknown query parameters/fragments, credentials, non-default ports, encoded/traversal paths, other hosts and other schemes are rejected. Arbitrary query parameters are never forwarded.

The browser fetch uses CORS, omitted credentials, no referrer, no cache, `redirect: error`, and a 15-second abort limit. The response must be a successful CSV/text response; redirects and HTML/login pages fail closed. Browser-side declared and streamed bytes are bounded to 1 MiB and UTF-8 decoding is fatal. The streamed transfer is covered by a 25-second end-to-end cancellation budget. The host's SignalR/JS interop configuration may still impose a smaller practical limit, so the full 1 MiB end-to-end transfer must be verified on the target host. The submitted URL is never fetched as-is. There is no server-side Google fetch or proxy, so this change introduces no server-side URL-fetch/SSRF path.

While import state is navigation-blocked, an owner-counted document capture guard prevents ordinary, unmodified primary clicks on same-origin links from navigating away. It is removed when the last import owner clears its warning. Modified clicks, non-primary clicks, and links targeting another browsing context remain usable. This click guard is a UI safeguard, not a general navigation lock: programmatic navigation (including direct use of a global Blazor navigation API) may bypass it. Forced reloads or tab closure can still lose transient page/circuit work; the existing unload warning remains.

## Limitations and fallback

This works only when Google makes the selected tab anonymously exportable and the browser permits the cross-origin response. A sheet requiring Google sign-in, OAuth, or an authenticated session is unsupported; CORS restrictions or provider redirects may also prevent retrieval. No credentials, API keys, cookies, or auth parameters are requested or sent to Google. The URL and CSV pass through transient Blazor Server circuit memory, but are not persisted to the database, browser storage, or application logs; the Google fetch itself is not proxied through the server. The existing local-file and paste paths were not converted to streamed interop and may still hit their existing SignalR/string-message size limits; this feature does not fix those separate paths. On fetch failure, the existing local CSV file selection or paste input remains available, and an earlier CSV value is preserved. Fetching a new source immediately invalidates any old preview/confirmation, but never starts preview or append automatically.

## Checks

Run `node scripts/event-import-spreadsheet-checks.cjs` for deterministic URL-normalization, rejection, mocked-fetch policy, byte-limit, content-type, HTML, UTF-8, redirect, timeout, and owner-scoped navigation-guard checks. Tests use mocked responses only; they do not contact Google or claim live-sheet compatibility. Parent integration is responsible for the actual browser run and fresh .NET/CI validation.
The fixed, authenticated sample CSV attachment remains downloadable while a draft is protected. The JavaScript function returns typed UTF-8 bytes; the Blazor IJSStreamReference result converter creates the stream reference (it is not manually double-wrapped). Parent browser checks verified 64 KiB and 1 MiB transfers with synthetic provider responses and no circuit errors. This is not a live Google compatibility claim.
