# イベントコメントと参加登録との併用

英語版 EVENT-COMMENTS.md を正本とする対応日本語版です。

## 実装した条件

現在イベントを閲覧できる認証済みユーザーは、演奏／観覧登録や必須設問への回答なしで
コメントを閲覧・投稿できます。一般ユーザーの投稿は開催日翌日の0時（Asia/Tokyo）より
前までです。開催日はUTCの日付ではなく開催時刻を日本時間へ変換して判定し、ちょうど
0時は受付終了。現在の全体／イベント管理者は終了後も投稿可能で、Hiddenも確認できます。
トランザクション内で有効性・セッション・SecurityStamp・実際の手動／自動フェーズを確認。
不正な日付や範囲外の日付は一般投稿を許可しません。

本文はtrim後3 Unicode文字以上（補助文字を2文字として数えない）。HTMLは通常の
エスケープ済みテキストです。既存の要求サイズ制限と65,536 UTF-16単位の検証上限で
転送／保存を保護し、小さな業務上の文字数制限を新設しません。公開一覧にはメール・
認証情報・操作ハッシュを出しません。本文と表示名はイベント閲覧者へ公開されますが、
未認証の一般インターネットには公開しません。

削除は現在の全体／担当イベント管理者だけで、一般ユーザーは自分の投稿も削除不可。
実画面で明示確認後、稼働DBの本文を物理削除し、監査には識別情報を記録します。
以前のバックアップや閲覧者のコピーまで消去する保証はありません。

## 保存と再送

移行 `20261013164240_AddEventComments` でEventCommentsとCommentOperationsを追加。
ユーザー／イベントFKと一覧索引を設定し、既存ユーザー・鍵・回答・割当・登録再送履歴・
メール／Push履歴・設定を変更／削除しません。操作台帳から削除対象コメントへのFKを
作らず、削除後も操作／イベント／操作者／対象・ハッシュ・日時だけを保持。
本文の別の平文コピーを台帳に残しません。

コメントのみの投稿は要求UUIDを本文のIDにも使います。同じ操作／操作者／イベント／
要求内容は結果を再表示し、別の内容・操作者によるID再利用を拒否。削除後に元の投稿を
再送しても本文を復活させません。削除も再送可能ですが現在の管理権限が必要です。
過去の結果でも現在の閲覧権と認証を確認します。締切前に確定した結果は締切後も確認
できますが、新しく投稿しません。ハッシュは再送／整合性用で、暗号化や完全忘却ではありません。

POST commentsは `{requestId,eventVersion,body}`、POST comment-deleteは
`{requestId,commentId}` を受け付け、厳格JSON・Origin・CSRF・サイズ制限を維持。
GET commentsはno-store、新しい順、同時刻はIDで安定整列。100件と `{at,id}` の続き情報を
返し、beforeAt／beforeIdを両方渡して過去分を取得します。境界のコメントが削除されても
時刻／IDカーソルは使えます。最新取得は一覧を置換し、ライブ同期や既に見た内容の回収は保証しません。

実Blazor `/events/<event>/comments` に業務基盤／参加登録から接続。スマホ入力・締切・
公開範囲・削除確認・過去分の取得に対応。書込み結果が不明なら、元のUUIDと入力を保持して
手動で同じIDを再試行し、自動で送信を繰り返しません。結果不明のまま再読込や新しいIDで
送信すると別の操作になるため、同じIDで結果を確認してください。

## 古い再送を壊さない参加登録併用

ParticipationEditへ任意commentを追加し、nullならシリアライズから除外します。
既存フィールドと順序は維持し、旧要求の指紋がバイト一致で再送できます。
旧結果JSONへ新プロパティを加えず、CommentCreated項目を登録と同じ要求UUIDで記録。
そのIDをコメントのみの操作に流用できません。代理登録の対象者ではなく操作者本人の投稿です。

- Register：全枠が個別失敗でも独立したコメント1件を保存可能。ただしフェーズ・必須回答・
  人数等の入力検証失敗は部分成功ではなく、操作全体をロールバックします。
- Spectate／Answers：成功後だけコメントを保存。AlreadySpectatorの成功0件では投稿しません。
- Release／RemoveSpectator：コメントは別に投稿します。
- 期限切れコメントは保存前に併用操作全体を拒否。最終ゲートで時刻を再確認して許可時刻を
  記録し、処理中に期限を越えた場合は登録／回答とコメントをまとめてロールバックします。
- 回答・参加者版・業務メールはコメント結果追加前の参加成功だけで判定。コメントのみの
  部分成功で回答を更新したり、登録メールを作成したりしません。
- 同じ要求UUIDで登録・コメント・メールを重複作成しません。削除後の再送結果は過去の
  確定結果であり、本文を復活させません。

参加画面ではCommentCreated成功時だけ入力を消去。結果不明なら元の要求を保持して編集を
止め、同じIDで再確認します。一般／代理登録の権限は変更しません。

## 検証と境界

```bash
dotnet run --project tests/Sem.CommentChecks -c Release
# 隔離ストレージ更新／実キー／ブラウザーハーネス内で使用
SEM_COMMENT_CHECKS=1 node scripts/e2e.cjs
```

実画面フラグはSEM_STORAGE_UPGRADE_COMMANDを使う既存ハーネス内でのみ実行。
event-comments.ymlで旧回帰を維持し、コメントの専用／実画面試験をDocker受入へ追加します。
合成ユーザーとローカルSMTPを使用し、実宛先・Push事業者へ送りません。

モックv33のグラフ／回答者表示／プロフィール導線・統合画面、QR受付とインポートは別工程。
本変更だけで配布・マージ・DXPの.env／鍵／ボリューム／ホスト名／稼働イメージを変更しません。
保持したい状態に破壊的Down移行を実行せず、検証済みの互換コピー／バックアップから戻してください。

後続の MEMBER-PROFILE.ja.md で投稿者／回答者の表示名を認証付き基本プロフィールへ接続します。未ログインQR／履歴は別工程です。
