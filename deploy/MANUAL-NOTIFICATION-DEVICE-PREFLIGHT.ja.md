# 手動通知の端末事前チェック（読取専用・配信未接続）

英語正本：`MANUAL-NOTIFICATION-DEVICE-PREFLIGHT.md`。

## 対象範囲

明示作成画面の後続。`ManualNotificationDevicePreflight.ReadAsync` で、受付済み宛先スナップショット1件と、期待する端末紐付け1件を現在DBで確認する。**内部の読取専用部品**であり、HTTP API・送信認可・宛先探索・配信ワーカー・端末別送信待ちではない。DI／ワーカーへ登録せず、追加移行やアプリからの呼出しもない。作成画面・ボックス・既存自動Pushの挙動は変えない。

すべての結果で `DispatchConnected=false`。紐付けが有効でも `PolicyPending` を返し、期限／TTL・ペイロード・リース・再試行・配信状態・送信待ちは作成しない。手動Pushは未稼働のまま。現在の資格変更で受付済みメッセージを書き換えない。

## 毎回現在DBで確認する事項

新しい1トランザクション内で次を読む。

1. 受付済み操作の宛先であり、イベント紐付けも一致する。後から参加した人を追加しない。
2. 対応するボックス行の本人と宛先スナップショットが一致する。
3. 有効・メール確認済みアカウント。Identity行はID／フラグ／stampだけを投影し、認証メール／プロフィール／メッセージ本文を取得しない。
4. 現在の有効フェーズ・DB上の管理権限による実効閲覧。
5. 現在の観覧登録、または同じイベントの未削除曲／定義を通る現在割当。これは `CurrentlyRegistered` という事実だけを返し、受付後の参加解除者へ送る／送らない方針を黙って決めない。そこまで評価できない早期拒否では不明（null）。
6. 端末が現在も宛先本人に紐づき、既存の許可エンドポイント・鍵の存在・stamp・未失効セッションの条件を満たし、期待する紐付け比較値と完全一致する。再登録・stamp／セッションの変更では古い紐付けを拒否する。

結果は固定された状態名・登録有無の事実・未接続フラグだけ。購読エンドポイント／鍵・stamp／セッション・人物ID・メッセージ・プロフィール／回答を返さずログにも出さない。配信の占有を取る処理ではなく、観測した事実が後の送信まで有効という保証もしない。将来の配信処理は承認済み方針と永続占有のもと、外部送信の直前に再確認する。

## 未決定・未実装

- 手動Pushの期限／TTLと、古い未稼働送信待ちを後から流すかの扱い。
- 受付後に参加を解除した人のPush扱い（今回の登録事実は方針決定ではない）。
- 端末別の永続送信待ち・重複抑止・占有／リース／再試行・外部受付不明の扱い・直前ゲート・配信接続。
- 定型ロック画面表示・本人認証を通るボックス遷移、手動通知種別の実物端末／Service Worker受入。

既存の自動配信へ流用接続せず、`PolicyPending` を送信可／送信済み／端末受信／既読と扱わない。DXP／.env／実データ／鍵／公開ホスト名・新配布・マージは変更しない。

## 検証

`dotnet run --project tests/Sem.ManualNotificationDevicePreflightChecks -c Release`。実際に移行した新規合成SQLiteとCore受付済みのボックス／宛先を使用する。現在アカウント・stamp／セッション／エンドポイント／端末本人／比較値、非表示イベントと現在の担当管理者、登録解除と保管スナップショット、未削除／削除済み演奏割当、後発参加者、ボックス本人不一致、送信待ち／監査／状態消費なし、取消伝播、モデル差分なし、秘密情報を含まない結果、実際の `Mode=ReadOnly` 接続を確認する。配信ワーカー・実Web Push・実ブラウザUI・本番適用の検証ではない。専用CIはRelease警告エラー化と全.NET回帰を行い、実績はPR／ダッシュボードへ記録する。
