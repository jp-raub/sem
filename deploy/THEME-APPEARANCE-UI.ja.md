# テーマ表示設定 UI

`/appearance` の表示設定画面は Core のテーマ表示 API を利用します。他の認証済みページでも同じモジュールが現在の利用者の解決済み表示設定を取得し、検証済みの4色を文書全体に適用します。`/events/{id}` および `/appearance?eventId={id}` ではイベント単位の設定も取得します。

## 設定と権限

- 個人・イベント・サイトの表示設定は Core データベースに保存します。優先順位は個人 → イベント → サイトで、配色と表示モードは独立して継承します。「端末設定に従う」はOSの配色設定を監視します。
- イベント管理者にはイベント設定を、サイト管理者にはサイト設定とカタログ管理を表示します。権限の最終判定はAPI側で行い、各リクエストで利用者・対象・権限を検証します。
- 下書きはブラウザー内のプレビューだけを変更します。「適用」だけが保存操作で、「キャンセル」は確定済み設定に戻します。表示設定の権威データとしてlocalStorageを使わず、クライアントから利用者IDを選択させません。
- カタログ名はテキストとして描画し、色は6桁の`#RRGGBB`だけを受け付けます。組み込みテーマはUIから削除できません。
- リクエストは現在の同一オリジン認証Cookieを使い、書込みごとにCSRFトークンを取得します。キャッシュを無効化し、リダイレクトを拒否し、応答サイズと25秒の時間上限を設けます。書込みは一度だけ試行します。結果が不明なら、利用者が明示的に再読込してサーバーの現在状態を確認するまで追加書込みを止めます。exactly-once配信を保証するものではありません。
- ダーク表示は承認済みモックの既定色（`#15201c`、`#202d27`、`#e1ebe5`）を使い、選択したアクセント色を明るくします。強制配色、キーボードフォーカス、レスポンシブ表示、動きを減らす設定に対応します。

## 検証

`node scripts/theme-appearance-checks.mjs`を実行してください。これはフロントエンドのソース／モック契約チェックであり、親担当者が実施する.NETビルド、APIテスト、CI、ブラウザー受入確認の代替ではありません。
