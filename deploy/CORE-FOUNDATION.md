# Core foundation — service, profiles and event administration

English source of truth. This is the first real business foundation, not a complete port of UI MOCK v33. It is layered on the approved external-test authentication/notification and explicit legacy-event-reset work.

## Implemented

- `/workspace`: interactive Blazor Server page, not another static mock. Native passkey authentication remains on `/`; the old route retains invitation and notification tests and links to the foundation. One edit form is active at a time; service-name/description preview is local until save, cancel does not write, and stale drafts are rejected instead of silently overwriting.
- Global service name (required, 60 UTF-16 units) and description (optional, 80). Only a current enabled/confirmed global administrator can save. Existing bootstrap name is used until the first save; the saved name is synchronized to `SiteStates.Name` without touching initialized/pending-bootstrap fields. SMTP From/display name remains independently configured; changing service name does not rewrite SMTP/VAPID/environment settings.
- Own profile: display name 60, reading 80, call name 60 and SNS links (service label 60, URL 500, bounded serialized payload). Reading uses NFKC and converts katakana to hiragana; call name allows hiragana/katakana. SNS accepts credential-free HTTP/HTTPS links, never fetches them server-side and renders links with no opener/referrer. Basic profiles are readable by authenticated enabled/confirmed members; authentication email is absent from shared profile/member DTOs. No target-user field exists in profile edits; unmapped JSON fields are rejected. A global administrator cannot edit someone else's profile through this service.
- Account read-only view: own current authentication email, role explanation and link to existing native passkey-addition UI. No pretend-working email change or recovery button.
- Formal `SessionEvents`: title/overview/location/required start/optional opening/announcement and foundation Hidden/View display modes. Opening equal to start is valid; missing opening remains distinct. Times are stored as canonical UTC ISO-8601 TEXT. The UI converts explicit Japan-local input; HTTP date-time input requires an explicit offset or Z, including case-insensitive JSON property names.
- Composite `EventAdmins(EventId,UserId)`, foreign keys, zero or multiple managers. Creation is global-admin only; assigned managers can edit only their event and its assignments. View permission is not management permission. Grant/removal never changes `AspNetUsers.IsAdmin`. Managers removed by a saved update lose write access even through an old browser identity. Formal event IDs are newly generated, never repurposed old test IDs.
- RowVersion for service/profile/event drafts. Event overview and manager-list replacement share a transaction/version. Successful changes append actor/target audit actions. Every write reloads account enabled/confirmed state, security stamp, session revocation and actual DB role inside a SQLite transaction; signed/cached role claims are not trusted as global permissions.
- Logout revokes the current unique authentication-session hash in `RevokedAuthSessions` and cancels its pending addition proof. HTTP and still-connected Blazor business operations reject that session. Other sessions are not revoked. Old native sessions without the unique session claim must log out/in before business operations. The middleware denies cross-origin Blazor transport requests with an Origin header; HTTP core mutations also require exact Origin and antiforgery. Private API and workspace HTML use no-store. API and web/asset rate-limit partitions are distinct, with the existing limits retained (60 API and 180 web requests per IP/minute); the first request no longer chooses the limit for both categories. Core-enabled browser acceptance paces API traffic across all contexts instead of weakening these limits.

## Storage upgrade and old data

`20261012162159_AddCoreFoundation` creates five new tables: ServiceSettings, UserProfiles, SessionEvents, EventAdmins and RevokedAuthSessions. Existing Identity/passkey, bootstrap, invitation/use counts, message/delivery/Push, proof and audit tables/rows are not dropped or rewritten by its Up migration. Profiles/settings are not fabricated for old accounts; missing optional profile fields read empty, and the old service name remains the fallback.

Before adoption or migration writes, startup refuses a DB that still contains old `Events`. Do not override this by deleting the whole DB or keys. Follow the separately verified stopped-copy preparation and explicit event/participation reset in `LEGACY-EVENT-RESET.md`, retaining the original whole `/data` archive including keys and original image/volume. The maintenance command may remain in a newer binary but accepts only the exact frozen pre-core schema/history; it refuses formal/future databases and cannot reset formal `SessionEvents`.

After core migration, old create/publish/join-test-event HTTP commands return 410 and their test-screen controls are removed. They are not an alternate enrollment path. Do not downgrade a core DB to an unsupported older binary or run EF Down against data you want to keep. Return to the untouched original image plus original volume under the established single-instance procedure.

No code change implies a PR merge, image delivery, DXP upgrade or live-data deletion. No `.env`, key, RP hostname or network alias is changed. DXP acceptance requires a separately verified exact image and a stopped fresh DB+keys backup/copied volume, with only one instance on the public route/alias. For the real Blazor page verify NPM/WebSocket forwarding through the existing same HTTPS origin; prior Push reception did not test this transport. Do not change proxy/network settings automatically.

### Docker restore ordering regression

The actual missing-framework defect was reproduced without Docker: restoring only the csproj, then adding Razor sources and publishing with `--no-restore`, produces no `blazor.web.js` or related static endpoints. Restore derives the implicit framework web assets from the available Razor sources. The Docker build now copies all `src/Sem.Web` source before restore, then publishes using the resulting assets. The clean full-source restore includes the framework script and routes; CI asserts both before HTTP/Blazor acceptance. A static-file middleware fallback cannot replace a framework file that was never published. No fixed SDK-version workaround or security-limit reduction is used.
