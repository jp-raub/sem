# プロフィール画像UI

既存の絵文字アイコンに加えて、任意のプロフィール画像を設定できます。絵文字はプロフィールのテキストとして引き続き編集・保存され、画像が存在するときだけ表示上で画像を優先します。

## 選択と保存

- ファイル選択UIはPNG・JPEG・WebPを案内します。クライアントは申告MIMEタイプが許可形式で、サイズが1 byte以上10 MiB以下のファイルを受け付けます。実際の内容検証とSVG・GIF・アニメーション画像の拒否はサーバーが担当します。
- ファイルを選択しただけではアップロードせず、デコードやプレビューもしません。画面に表示するのはファイル名とバイト数だけです。アップロードには明示的なボタン操作が必要です。
- サーバーはメタデータを除去した正規化PNGだけをデータベースに保存します。最大辺は512px、サイズは1 MiB以下です。元画像は保持しません。クライアントは選択した `File` を `fetch` で直接送信し、Blazor／SignalR回路内に複製しません。
- 保存画像は既存の認可済みプロフィールDTOに含まれる `imageDataUrl` からのみ表示します。値は厳密な `data:image/png;base64,` URL、正規形のBase64、PNGシグネチャ、デコード後1 MiB以下を満たす必要があります。公開画像URL、リモート取得、SVG、HTML描画は使用しません。保存画像がある間は表示上で絵文字より優先し、画像がない場合は絵文字（または中立的な絵文字プレースホルダー）を表示します。

## APIとライフサイクル

- 既存の編集・基本プロフィール・ゲストQR DTOに `imageDataUrl` と `imageRowVersion` を含めます。画像がない場合の行バージョンは `0` です。
- アップロード：`POST /api/core/profile-image?expectedActor=<cookie actor>&rowVersion=<imageRowVersion>`。選択ファイルをバイナリー本文として直接送り、検証済みの `image/png`、`image/jpeg`、`image/webp` をContent-Typeに指定し、現在の同一オリジンCSRFトークンを付けます。
- 削除：`POST /api/core/profile-image-delete?expectedActor=<cookie actor>`。JSON `{ "rowVersion": <imageRowVersion> }` と現在の同一オリジンCSRFトークンを送ります。
- 成功応答は `{ "rowVersion": number, "width": number, "height": number }` です。成功後、編集画面は既存のプロフィールDTOを再読込し、サーバーで正規化された画像または絵文字フォールバックを表示します。
- リクエストは現在の同一オリジン認証Cookieを使い、リダイレクトを拒否し、25秒で打ち切ります。コンポーネント破棄時は実行中リクエストを中断し、所有者世代と現在のルートを検証して再マウント後の画面を古い応答が更新しないようにします。
- 書き込み結果を確認できない場合、自動再送や再アップロードはしません。選択ファイルをクリアし、ユーザーが明示的にプロフィールを再取得してサーバー状態を確認するまでプロフィールの書き込みをロックします。`401`／`403` では編集者情報と画像を画面から消去します。
- 既存のゲストQRプロフィール応答に正規化画像を含めます。QR用の新しいエンドポイントや公開画像URLは追加しません。QR期限切れ時は画像を含むゲストプロフィールDOM全体を消去します。

編集・基本プロフィール・ゲストQRのJSON応答上限は4 MiBです。登録履歴の上限は4 MiBのまま、CSRF応答上限は64 KiBのままです。Blazorへのプロフィール／履歴転送は上限付きJSストリームを維持し、全体のSignalR受信上限は変更しません。

## チェック

合成ブラウザー通信チェックを実行します。

```sh
node scripts/profile-image-transport-checks.mjs
node scripts/profile-history-transport-checks.mjs
```

リリース前に、承認済みブラウザーfixtureで、正規化された512×256 PNGがそのネイティブ寸法で表示されること、削除後に絵文字フォールバックへ戻ること、認証Cookie変更後の `403` で画像が表示されないこと、ゲストQR期限切れ時にプロフィールとともに画像も消えることを確認してください。これらUIチェックでは `dotnet`、共有ホスト、本番環境の検証は行いません。
圧縮後のファイルが10 MiB以内でも、展開後の解像度や処理負荷が過大な画像は拒否される場合があります。バックエンドの安全上限を維持します。
