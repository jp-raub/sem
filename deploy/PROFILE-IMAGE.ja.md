# プロフィール画像（バックエンド）

英語版 `PROFILE-IMAGE.md` を正本とし、本書は対応する日本語訳です。

プロフィール画像は任意機能で、本人だけが管理します。ユーザーIDをキーにした専用の `ProfileImages` SQLiteテーブルに保存し、`UserProfiles`、基本プロフィール編集、認証／パスキー情報、QRの期限／失効状態は変更しません。既存のプロフィール編集・メンバープロフィール・有効なゲストQR投影の認可経路が `ProfileView` への正規化済み画像の包含を決定します。公開画像IDの取得APIはありません。

## HTTP契約

- 保存：`POST /api/core/profile-image?expectedActor=<現在のCookie操作者>&rowVersion=<画像版>`。本文は生の画像バイト列で、`Content-Type` は `image/png`、`image/jpeg`、`image/webp` のいずれかを正確に指定します。
- 削除：`POST /api/core/profile-image-delete?expectedActor=<現在のCookie操作者>`。厳密なJSON本文 `{ "rowVersion": n }` を使います。
- どちらも同一オリジンの `Origin`、既存のCSRFヘッダー／Cookie、および現在認証済みで有効・メール確認済みの操作者（最新のsecurity stamp、現行セッションclaim、失効セッション記録なし）を必要とします。厳密なクエリ検証を含むこれらの確認は本文読込前に実施します。操作者はCookie主体と一致しなければならず、クライアントが他ユーザーを指定することはできません。
- アップロードは最大10 MiB、削除JSONは最大64 KiBです。画像処理スロットは同時2要求までで、満杯の場合は本文を消費する前に429を返します。Kestrelのアクション別上限にはフレーム用16 KiBの余裕を加え、ストリーム読取側で実際の上限を強制します。
- どちらも独立した画像行バージョンを比較し、変更と秘密を含まない監査記録をトランザクションで保存します。応答は `{ "rowVersion": n, "width": n, "height": n }`、削除時の寸法はゼロです。基本プロフィールPUTは画像状態を変更しません。

## 正規化と保存

MIMEとマジックバイトを確認し、ファイルパス、URL、SVG、GIF、その他形式は受け付けません。ピクセルデコード前にPNG APNGのアニメーション制御チャンク、WebPのアニメーションチャンク／フラグを拒否し、画像リスト長も1に制限します。ImageMagickには、コーダー／モジュール制約（PNG/JPEG/WebP読込、PNG書込のみ、全デリゲート無効）、ネイティブメモリ／ディスク／面積／寸法／リスト数／スレッド／時間／プロファイル上限、デコード前の2,400万画素上限、待ち行列を作らないアップロード／デコードセマフォを設定します。

検証済み静止ラスタ画像をEXIF方向に合わせてから、プロファイル・コメント・GPSを含むメタデータを除去します。長辺が512 pxを超える場合のみ、縦横比を保って縮小し、拡大しません。PNGに変換し、出力が1 MiBを超える場合は拒否します。保存するのは正規化PNGのバイト列と寸法のみです。元画像はメモリ内だけで扱い、ファイルに保存せず、ログ／監査にも含めません。削除後はデータ空・寸法ゼロの墓標行を残して画像版を必ず増加させ、削除後再作成によるABA競合を防ぎます。`ProfileView` にはNULL許容の `ImageDataUrl`（正規化PNGのみ）と独立した `ImageRowVersion` を追加します。base64投影サイズは保存時の1 MiB上限により制限されます。

## マイグレーションと実行環境

追加マイグレーション `20261015153000_AddProfileImages` は専用ユーザー別テーブルと制限付きユーザー外部キーだけを作成します。マイグレーションDesignerとEFモデルスナップショットには対応する `ProfileImage` エンティティを追加し、既存プロフィール／パスキー行は書き換えません。Magick.NET-Q8-AnyCPU 14.17.2にはLinux x64ネイティブ資産がNuGetパッケージに含まれるため、現行の.NET 10 Linux DockerランタイムにImageMagick OSパッケージを追加する必要はありません。復元済みパッケージの `runtimes/linux-x64/native` 資産で確認済みですが、配備前にDockerイメージのスモークテストを実施してください。実行時マイグレーション／DBバックアップは既存の配備手順に従います。

専用チェック：`dotnet run --project tests/Sem.ProfileImageChecks`（形式、サイズ、向き／縮小、出力、アニメーション／不正画像拒否）および `dotnet run --project tests/Sem.ProfileImageHttpChecks`（合成認証、本文読込前拒否、CSRF／Origin、版／ロールバック、プロフィール投影、ゲスト期限）。実SMTP／Push、公開画像ホスティング、外部URL取込、本番操作、配備はテスト範囲外です。
