# メンバープロフィール・任意設問・24時間QR共有

英語版 MEMBER-PROFILE.md を正本とし、本書は対応する日本語版です。

既存の認証付きメンバープロフィール `/profiles/<不透明なユーザーID>` と、プロフィール／登録履歴の既存通信経路は維持します。有効かつメール確認済みのメンバーは、対象者の現在の表示名・正規化済みの読み・対面での呼び・絵文字アイコン・本人が保存したSNSリンク・プロフィール設問の回答を確認できます。プロフィールQRの応答にはメール、認証／セッション情報、招待情報、登録履歴を含めません。既存の登録履歴は別の認証付き通信であり、QRベアラーからは利用できません。

## プロフィール設問と回答

全体管理者はプロフィール設定画面でサービス共通設問を管理します。設問は自由記述（`Text`、最大200文字）またははい／いいえ（`YesNo`）で、必須フラグはありません。作成後に回答形式は変更できません。回答済みでも文面編集・停止・並び替えが可能です。停止した設問は新たな回答編集の対象外となりますが、既存回答は保持します。回答が1件でもある設問は削除できません。回答は任意で、自由記述は最大1000文字、はい／いいえは `YES` または `NO` に限定します。現在の回答は、既存のプロフィール画面で有効かつメール確認済みのメンバーに自動公開されます。承認済みの有効設問表示に合わせ、停止設問と保持された回答はメンバー・匿名QR表示から除外します。DB上の回答は保持され、削除防止の対象です。

プロフィールには絵文字アイコンを1つ指定できます。画像の保存・保持・バックアップ・復旧方針は未確定のため、画像アップロードは実装していません。アイコンは通常のエンコード済みテキストとして表示します。

## 匿名プロフィールQR

QRの発行・再発行は本人だけが `/profile/settings` から行えます。読み取り専用の `GET /api/core/profile-qr` は状態だけを返します。発行・再発行はCSRF／Originを検証するPOSTで、現在のCookie操作者と行バージョンに結び付けます。暗号学的にランダムなベアラーの有効期限は正確に24時間で、再発行は保存済みハッシュ／版を原子的に置き換えて旧トークンを直ちに失効させます。読取では期限を延長しません。DBにはSHA-256ハッシュのみ保存し、平文ベアラーは保存しません。

生成QRは `/profile/share#token=…` を指します。フラグメントは最初のページ要求では送信されません。ページはブラウザー履歴からフラグメントを消してから、同一オリジンのCSRF付きPOST本文でトークンを照合します。APIクエリではトークンを受け付けません。本人専用SVG GETはHTTPヘッダーでベアラーを受け取り、要求URLには載せません。QR／プロフィール応答はno-store、`Referrer-Policy: no-referrer` を設定し、共有ページは第三者アセットを読み込みません。本人画面では平文ベアラーをメモリ内だけに保持します。再読込後は、有効QRであっても明示的に再発行して新しい画像を表示します。

ベアラー読取のたびに有効期限と対象アカウントの現在の有効状態・メール確認状態を確認し、プロフィールと回答の最新状態を読み込みます。QRが許可するのは現在の基本プロフィール・回答・保存済みSNSリンクだけです。メール、招待／認証秘密、登録履歴、イベント閲覧、受付、アカウント操作は許可しません。アカウント停止またはメール未確認化後のQR読取は拒否します。SNSリンクを自動取得・埋込みしません。

## 保存と検証範囲

追加EFマイグレーションで絵文字欄、設問／回答、ハッシュのみのQR資格情報を追加し、一意制約・外部キー・入力制約を設定します。既存プロフィール行のアイコンは空文字で初期化し、既存SNS／プロフィール内容、イベント／認証テーブルは書き換えません。モデルスナップショットとマイグレーションDesignerを更新します。

単独のCore／HTTP合成テストは一時SQLite、合成Cookie主体、CSRF／Originヘッダー、Push no-opを使用します。権限、型不変、回答長・保持、QR期限／再発行、本人専用SVG、フラグメント／本文通信、メール／履歴の除外を確認します。実ブラウザー、複数端末、PostgreSQL、本番プロキシのアクセスログ、実SMTP／Push、配備受入の完了を意味しません。QR照合APIの本文をログに記録しないでください。インフラのアクセスログではベアラーヘッダーと要求本文を記録しない設定が必要です。合成スイートは `dotnet run --project tests/Sem.ProfileExtensionChecks` と `dotnet run --project tests/Sem.ProfileExtensionHttpChecks` で実行します（このワークスペースでは `PATH=/data/dotnet:$PATH`、`DOTNET_ROOT=/data/dotnet`、検証済み `NUGET_PACKAGES` を指定）。本増分では本番エンドポイント、SMTP、Push、外部ホスト名、鍵、ボリューム、共有ブラウザー、配備先を変更しません。

QR解決応答は確認済みの期限ヘッダーを返します。ブラウザーは新しいフラグメントの処理前に旧表示を消し、古い応答を無視し、期限到達で表示を消します。サーバーの期限確認が引き続き認可の根拠です。

HTTPプロフィール編集は現在セッションの事前認可後、厳密なJSONを最大1 MiBまで受け付けます。他の新プロフィール書込は64 KiBの上限付き読取です。SNS JSONは既存の32,000文字制限を維持します。ブラウザーのJSON読取は厳密なUTF-8ストリームで2 MiB（CSRFは64 KiB）まで、通信予算は25秒です。編集画面の認可失敗時は旧プロフィールとQR表示を消します。

発行・再発行と操作者／対象者の監査は同一トランザクションで保存し、監査にベアラーは含めません。編集画面の要求・コールバックは所有世代に紐付き、破棄後は中断・無視します。遅れて完了したモジュール読込は初期化せず破棄します。
