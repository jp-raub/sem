# 認証付き基本プロフィールと投稿者／回答者の導線

英語版 MEMBER-PROFILE.md が正本で、本書は対応する日本語版です。

`/profiles/<不透明なユーザーID>` に実Blazor基本プロフィールを追加し、コメント投稿者と
公開集計の回答者から移動できます。既存のReadProfileAsync／認証付きプロフィールAPIを
再利用し、新しい未ログイン公開データ源や権限ルールを作りません。現在の有効性・メール確認・
SecurityStamp・セッションを確認し、対象者も有効かつ確認済みである必要があります。
歴史上の回答／コメントの表示名は残っていても、停止後のプロフィールは閲覧できません。
その場合は一般的なエラーを表示し、古いプロフィールの内容を残しません。

表示名・正規化済みの読み・対面での呼び・本人が保存したSNSリンクだけを表示します。
メール・非公開のイベント回答・セッション・連絡先フィールドは出しません。
通常のRazorテキストとしてエスケープし、SNSは資格情報なしの絶対HTTP／HTTPSだけ。
noopener noreferrer付きの新規タブで開き、自動取得／埋込みしません。ユーザーIDはURL
エンコードし、外部URLへの移動先として使わせません。

実画面の接続後に読み込み、画面移動／再取得／エラーで旧内容を消去。
移動前の非同期応答を後から表示しません。明示再取得方式で、既に見られた内容を回収する
保証はありません。DB移行・新フィールド・公開フラグは追加せず、承認済みの認証済み
メンバー間の基本プロフィール公開方針を維持します。

未ログイン用プロフィールQR・24時間リンク・イベント受付QR・登録履歴・追加設問・
v33の最終プロフィールポップアップとは別の段階です。イベント受付トークンを公開
プロフィールの認証情報に流用しません。今回は既に許可されている基本プロフィールと、
イベントの表示名導線をつなぐ実装です。

```bash
# 既存の隔離実キー／ストレージ更新／実Blazorハーネスへ追加
SEM_MEMBER_PROFILE_CHECKS=1 node scripts/e2e.cjs
```

フラグはSEM_STORAGE_UPGRADE_COMMANDを使う受入内で実行し、本番の単独試験ではありません。
member-profile-view.ymlで従来の全試験を維持し、スマホ・リンク・エスケープ・未認証拒否を追加。
合成データ／ローカルSMTP／隔離ブラウザーのみ。SNSの外部ページは実際には訪問しません。
マージ・新配布・DXPの.env／鍵／ボリューム／ホスト名／稼働イメージは変更しません。
