# 旧テストイベントの一度限りのリセット

英語正本は `LEGACY-EVENT-RESET.md`。本書は対応する日本語版。

## 対象と現在地

旧外部テスト版のイベントを削除してよいという承認に基づき、正式フェーズ設定や演奏／観覧区分を推測して移植せず、イベントを新規作成する。これは本体基盤への最初の前提処理であり、正式業務機能の実装完了やDXP適用を意味しない。PRは勝手にマージしない。

**正確に対応する旧テストスキーマ**の `Events` 全件と、それに紐づく `Participations` を同じトランザクションで削除し、件数付きのホスト保守監査を1件追加する。Identityユーザー／パスキー／セキュリティスタンプ、サービス状態、招待依頼／使用数、メール証明、メッセージ、配送、Push端末、過去監査、マイグレーション履歴は保持・照合する。保護鍵ディレクトリ、.env、SMTP／VAPID、RPホスト名は操作しない。削除済みイベントへの監査参照は過去履歴として残す。通知本文を外部キー扱いして曖昧一致で削除しない。`Kind=Reminder` は `Subject` にイベントIdを保存する。配送行は保持するが、既存ワーカーはイベントがなければ通知を作らない。送信済み履歴や無関係な予約テスト／メール／Push配送は保持する。

## 安全条件

- 未指定時は読み取り専用の検査のみ。変更には `--apply`、検査したDBのSHA-256、イベント／参加件数、新規の絶対パスのDBバックアップ先を明示する。
- 対応対象は履歴なしの固定基準スキーマ、管理された基準移行のみ、基準＋パスキー追加証明の2移行。残存したEF移行ロック、未知／空／非連続の履歴、追加・欠落したテーブル／列／インデックス／ビュー／トリガーを拒否。正式モデルや将来の移行を追加したビルドでは実行しない。
- 孤立した参加記録、SQLite整合性／外部キー違反は削除前に拒否。勝手に削除対象を広げない。
- 必ず停止したコピーDBで行う。DBのシンボリックリンク、非空のWAL／SHM／journal、WALモードを拒否。delete／truncate／persistモードのみ対応。ロック取得はアプリ停止の証明ではない。稼働中のDBでサイドカー削除やjournal変更をして回避しない。
- 適用時は即時トランザクションで他の書き込みを拒否し、ロック待ちは最大1秒とし、ハッシュと件数を再照合する。新規専用ファイルを0600で作りDBの完全コピーとハッシュを検証後、参加→イベントを削除。既存バックアップは上書きしない。コミット前の例外は両削除と監査をロールバックする。途中失敗時にも作成済みバックアップを保持する。
- コミット前に保持対象全テーブルと旧監査の不変、DB整合性／外部キーを再確認。既に空なら何も変更せず、監査やバックアップを追加しない。
- 通常起動、EF移行、HTTPからは実行しない。CLIは設定読込み、移行、Web／通知ワーカーの起動前に終了する。出力は件数・ハッシュのみで、個人の行や秘密情報を出さない。

## 実施順序：コピー先のみ

1. 実イメージ・ボリューム・プロジェクトを確認し、既存の停止中バックアップ手順で **DB＋keysを含む `/data` 全体**を権限制限して保存、チェックサムを記録する。保守処理のDB単体バックアップは補助であり、DB＋鍵の代用ではない。
2. 別の空ボリュームへ1654:1654で復元し、元イメージ／元ボリューム／アーカイブを保持してDB／鍵ハッシュを照合。復元アプリを元と同じ公開経路／alias `sem` に同時起動しない。
3. 別途検証した保守版イメージを使う。既に配布した `proof-6c5e396d788a` には本変更はない。以下は実イメージを受け取ってから使う例であり、今すぐDXPで実行する指示ではない。`COPY_VOLUME` は検証した停止中のコピーであり、元／稼働中ボリュームを指定しない。

```bash
COPY_VOLUME='<確認済みの停止中コピー先>'
RESET_IMAGE='<確認済みの保守版イメージタグ>'

docker run --rm --network none \
  --cap-drop ALL --security-opt no-new-privileges:true \
  --mount "type=volume,source=$COPY_VOLUME,target=/data" \
  "$RESET_IMAGE" --legacy-event-reset --database /data/sem.db
```

4. `Status=inspection-only` と `Events`／`Participations`／`DatabaseSha256` を確認し、想定外なら停止。承認対象は旧テストイベントのみであり、将来の正式イベントではない。検査結果JSONは非公開で保管する。
5. 同じイメージ／ボリュームで検査した値をそのまま指定し、新しいバックアップ名を選ぶ。アプリ更新を自動実行する処理ではない。

```bash
docker run --rm --network none \
  --cap-drop ALL --security-opt no-new-privileges:true \
  --mount "type=volume,source=$COPY_VOLUME,target=/data" \
  "$RESET_IMAGE" --legacy-event-reset --database /data/sem.db \
  --apply --expected-sha256 '<検査したDBハッシュ>' \
  --expected-events '<検査した件数>' \
  --expected-participations '<検査した件数>' \
  --backup '/data/sem-before-event-reset-UNIQUE.db'
```

6. 再検査でイベント／参加0件を確認し、DB単体コピーと元アーカイブを保持。既存の同一公開URL・単一起動の受入手順で、元パスキーでのログイン、アカウント／権限、招待使用数、既存メッセージ、再登録なしPush、新規予約通知を確認する。SQLite行保持から実送信や保護鍵の検証成功を推定しない。
7. 正式イベント作成、プロフィール、複数管理者、業務マイグレーションは次の実装単位。旧テスト画面を完成した本体UIとしない。正式イベントには新しいIdを使い、削除したIdを再利用しない。

## 復帰

失敗時に推測した対象で再実行したり、データ／鍵を削除しない。秘密を伏せた結果、バックアップ、元ボリュームを保持する。第一の復帰先は元イメージ＋未変更の元ボリューム。DB単体コピーを戻す場合は停止中に対応する保持鍵と組み合わせる。新しい移行済みDBに対応しない旧バイナリを起動しない。通知ワーカーを停止し、復元後も同時起動しない。この処理は、既に外部送信した通知を取り消すトランザクションではない。

## 検証

`dotnet run --project tests/Sem.LegacyResetChecks -c Release` は合成データのみで、旧／基準／追加証明スキーマ、読み取り専用検査と拒否時の無変更、完全バックアップ／0600、保持行とパスキーバイト、関連削除、監査／反復無変更、古いハッシュ／件数、未知スキーマ／履歴、孤立参照、外部キー違反、サイドカー、WAL、バックアップ衝突、他の書き込みロック、CLIを確認する。専用CIには既存ストレージ／追加証明／HTTPS統合試験も残す。DXPの実データは使わない。
