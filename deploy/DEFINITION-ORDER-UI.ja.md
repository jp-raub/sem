# パート定義の下書き並べ替え

基準 main `5212636e54802ee3327312c85603befb1c6da09f`、採用モック `9cf8b031258fa1c9afe9668f54e61f002c4bce17/mock` と UI MOCK v33 の手動並べ替え契約に合わせる。

- サービスのパートプリセットとイベント定義の同じ編集画面へドラッグハンドルを追加。行の名前ボタンは従来どおり編集欄を開く。
- ドラッグ元をドロップ先の最終位置へ動かし、間の行の相対順を保つ。先頭→末尾は末尾へ、末尾→先頭は先頭へ移動する。同位置・存在しないIDは変更しない。
- 上下ボタンを残し、キーボード・ドラッグ非対応／タッチ端末の代替とする。行名付きのアクセシブル名と移動結果の通知を付ける。タッチの代替は上下ボタンであり、HTML5ドラッグを全タッチブラウザーで保証するものではない。
- 両操作は同じ未送信リストだけを更新する。最後の保存まで共有しない。取消は保存済み順へ戻し、競合は下書きを保持して全件拒否する。既存の使用中定義・担当済み枠の削除保護を緩めない。
- 編集外・処理中・編集モーダル中はドラッグを受け付けない。読込・取消・モーダル開閉・保存・対象切替でドラッグ元を破棄する。イベント／サービス、本人・stamp・sessionの切替や破棄後の遅い応答は共通の編集寿命境界で拒否し、同じ対象の再描画では下書きを初期化しない。
- 行を安定したIDで保持し、横にはみ出す表は区画内だけでスクロールする。

保存API・DB/migration・認証・通知方式は変更しない。プリセット更新は既存イベントへ遡及せず、定義や割当を勝手に整理しない。専用URLと既存保存単位を維持する。

## 実ブラウザーで検出した属性不具合

Razorのbool値ではHTML列挙属性 `draggable` が空属性になり、ブラウザーの実際の `draggable` がfalseになることを検出した。文字列のtrue／falseを明示する。同じ形式の既存タイムテーブルも1箇所を修正し、既存の共通下書きテストへ実ドラッグの回帰を追加する。上下操作で並べ替えられたことをドラッグ成功の代用にはしない。
