# イベントの曲・演奏パート枠

検証済み設問ブランチに積み重ねる管理機能の段階実装です。参加登録・タイムテーブルの完成や本配布ではありません。英語版 EVENT-SONGS.md を正本とします。

## 保存・移行・保持

追加移行 AddSongsAndSlots は Songs／SongParts とイベントの DefaultPrepSeconds を追加します。改良後のv33モックに合わせ既存・新規の正式イベントとも初期600秒。ユーザー・ネイティブキー・保護鍵・招待・メッセージ・通知・フェーズ・管理者・定義・設問／回答を保持します。曲・定義・フェーズのイベントIdを含む複合キーで、別イベントを参照する枠をDBでも拒否します。制約追加のためSQLiteが既存テーブルを再構築する場合があります。停止コピーとバックアップを用いる受入手順を維持し、元ボリュームの削除や全DB初期化はしません。

- 曲：固定Idとイベント、曲名／アーティスト各200文字以内、演奏1秒以上、準備秒数・順序・削除済み印。準備nullはイベント既定の継承、0は準備なし。イベント既定にも0を明示設定できます。
- 新しい管理枠は各定義1つ、曲には1枠以上。改名・順序・時間変更でも既存枠Idと担当参照を保持。
- 枠は曲・イベント内定義・実在ユーザー・登録元フェーズへの削除制限FKを持ちます。ユーザーとフェーズは両方nullか両方あり。今回は保存基盤のみで、参加登録／担当設定／解除APIは提供しません。試験で直接投入する担当は合成保存データであり、実参加の成功とは区別します。
- 枠で使用中の定義は、未割当でも削除・声／楽器分類変更を拒否。同じIdでの改名は可能。サービスプリセットとイベント内コピーは独立。
- 担当者のいる枠／曲の削除は拒否。旧データに同種の複数登録済み枠があれば、編集を拒否して勝手に統合しません。未割当重複だけは1枠へ整理し、1つの割当枠があればそのIdを残します。未使用の削除曲は印を残し、未割当枠を除去、曲Id再利用を拒否。

## API・実画面

管理者限定 GET／POST `/api/core/songs?id=<eventId>` と実Blazor `/events/<eventId>/songs`。現在のDB上の有効性・メール確認・SecurityStamp・失効と全体／イベント管理権限を再確認します。Origin／CSRF、本文64KiB、不明項目拒否、共通イベントRowVersion、原子的保存を維持。DTOから担当を変更できず、計画は割当有無のみ返して担当ユーザーIdは返しません。防御上の上限は下書き300曲／100定義で、参加人数や商品仕様の新たな制限ではありません。

曲名クリックで編集、追加、安定Idによる上下移動、下書き反映・最終保存・取消。時間入力 m:ss／h:mm:ss で秒を保持。準備継承時は個別入力無効、0:00は明示的な準備なし。パネル中は背景操作を無効化。担当枠のUIを無効化してもサーバーで再検査します。競合・入力エラー時は下書きを保持し、認証失効時は私的管理状態を消去します。
