# 本人の実パート開始Push配信

## 承認済み動作

本人が現在閲覧できる開場・曲・転換の任意パートを選択する。自分の演奏曲に限らず、既定OFF・設定は本人所有。管理者も他人の選択先を指定できない。予定時刻／準備開始の通知とは別。

有効期限は承認済みの **実Start＋10分と実Endの早い方**。End未記録なら10分まで、期限ちょうど以降は送らない。ON／再ON前のStartは遡らない。Start実績なしは待機し、予定／見積で補完しない。Endと同時に記録される次の転換Startは、その転換の本人設定に従う。次の曲のPrepStartでは曲の開始通知を発生させない。

## 保存と移行

移行 `20261013160039_AddPartStartDelivery` で本人設定の有効化時刻／進行版と既存端末別台帳の `PartStart` 種別を追加。既存ONはEnabled・Version・ChangedAtを維持し、移行時のUTC時刻と現在の進行版を境界として記録する。選択を保持しつつ、既に記録された開始をまとめて送らない。既存OFFはOFFのままで過去の配信を捏造しない。同じONは境界を動かさず、OFFは版を維持して境界を空にし、再ONは新しい境界。

[自動配信](EVENT-PUSH-DELIVERY.ja.md)の旧端末登録を一度やり直す条件は維持。新登録は通常再起動後も残る。本人設定は端末許可／認証結び付けを作らない。VAPID未設定を画面に分離表示し、ワーカーは送らない。稼働.env・ホスト名・鍵・ボリュームは変更しない。

現在のパートの存在／種類と、検証済み凍結計画・実績の両方に一致することが必要。実Start／操作の不変識別からフィンガープリントを作り、無関係な見積／進行版の変更で同じStartを作り直したり誤取消ししない。実Endは送信時に毎回期限へ反映。削除済みパート、不正進行、境界欠落、未来の実績は送信不可。

## 配信と安全性

自動ルールと本人設定を一つのイベント巡回カーソルで公平に処理する。宛先はその設定の本人のみ。演奏／観覧登録は不要だが、現在の閲覧権は必要。本人ON／設定版、検証済み実績、期限、有効／メール確認済みユーザー、実効フェーズ／閲覧権、スタンプ、失効していないセッション、変化していない端末を確認し、リース更新後に最終ゲートでも再確認する。

既存の永続claim、2分リース、最大5回再試行、再登録を消さない404／410購読解除、安定Topic／タグ、複数端末でも論理通知一件のメッセージを再利用。本文は一般的な説明と実Start日時のみで、私的なイベント／曲／転換名、メール、回答を含めない。タップ先は再検証した認証付きイベントのタイムテーブル。TTL／タイムアウトを意図的に残存期限より延ばさない。

Acceptedは配信事業者受理であり、端末到着ではない。外部受理後・ローカル保存前の停止／タイムアウトでは重複再試行の余地が残る。安定Topic／タグはまとめる仕組みであり厳密な一回配送ではない。受理済み通知は取り消せず、期限後到着は一般的な期限切れ案内のみ。自動配信と同じ限界を維持する。

## 検証・適用境界

```sh
dotnet run --project tests/Sem.PartStartDeliveryChecks -c Release
dotnet run --project tests/Sem.EventPushDeliveryChecks -c Release
node scripts/event-push-service-worker-checks.cjs
```

専用試験はPR23データ入り移行、ON／受理履歴保持、全パート種、参加登録不要、予定／準備で代替しない条件、排他的期限、履歴／再ON抑止、OFF／非公開／削除／失効、直前再確認、見積変更時の同一性、再起動／再試行を検証。実事業者への要求は輸送試験で偽物を使い、実端末到着を推定しない。既存全回帰・SMTP・実キー・データ保持移行・スマホ／Blazor・Docker試験を維持する。

前進移行と検証済みバックアップ／コピーへの切戻しを優先する。PartStart台帳が作成された後に旧種別制約へDownすることは安全に成立しない。履歴を削除して強行しない。CI成功だけで配布・適用・マージしない。
