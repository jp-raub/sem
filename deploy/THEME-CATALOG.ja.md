# テーマカタログ永続化（Coreのみ）

テーマカタログは `ThemeCatalogEntries` に保存します。1回限りのEFマイグレーションでテーブルを作成し、純粋なテーマ値ライブラリの承認済みデフォルト10件を登録します。アプリ起動時の再シードは行わないため、その後の管理者編集は保持されます。既存のアプリケーションテーブルおよび行は変更しません。

`CoreFoundationService.ReadThemeCatalogAsync` は、認証済みで有効なアカウント、最新のセキュリティスタンプ、未失効セッションを持つユーザーに限り、ID・名前・4色・組み込みマーカー・行バージョンのみを返します。認証済みユーザーは読み取り可能です。`AddOrUpdateThemeAsync` はさらに全体管理者権限を要求します。イベント管理者権限だけでは書き込めません。新規IDはサーバーが生成します。更新時は完全一致のIDと期待行バージョンが必要です。組み込みテーマは編集できますが、組み込みマーカーは変更できません。検証とDB制約により、小文字ASCIIのkebab-case ID、長さ制限付きの名前、大文字の `#RRGGBB` 保存形式、非負の行バージョンを強制します。

削除APIは設けていません。選択参照と使用中保護が整うまでは削除を行いません。テーマ選択APIや設定項目も含みません。

**対象範囲:** 本機能はカタログ保存とCoreの管理処理のみです。テーマはまだアプリ内で選択・描画できません。本番完了を示すものではありません。デフォルト値は引き続き既存のモックIDに対応します。ユーザー向けテーマ機能が本番提供されたことを意味しません。

## 検証

リポジトリのルートで `dotnet run --project tests/Sem.ThemeCatalogChecks` を実行します。一時SQLiteの移行検査も、アプリ／設計時ファクトリーと同じIdentityスキーマVersion 3を構成します。既存の合成Passkey行とイベント／プロフィール／サービス設定を保持し、スナップショット一致、認可、制約、版管理、監査の原子性、読取無変更、初回のみの初期化を確認します。試験に合わせて移行警告を抑制したり、既存Identityモデル定義を削除したりしません。
