# 手動通知の端末単位配信部品（未登録）

## 範囲

永続キューに `DispatchOneAsync(deliveryId)` を追加します。DI／HTTP／ワーカー／走査処理へは登録せず、起動時にPushを有効にしません。別PRのPKCS10.0.13修正を基底から取り込みます。DB移行、ボックス追加、既読変更、SMTP呼出し、自動Push動作の変更はありません。

本番 `IEventPushTransport` は注入可能ですが、検証では偽送信とメモリ内HttpMessageHandlerだけを使い、実Push接続先には通信しません。実基盤／実機受入ではありません。

## I/O直前の確認

送信未設定なら占有しません。キューを一意に占有後、1トランザクションで確定件名と現在有効な端末だけを取得し、確定宛先／ボックス本人、受付印、現在の有効化／世代、アカウント、実効閲覧、参加登録、紐付け／stamp／セッション、正確な所有者、有効リース、固定期限を再確認します。Pushのために複数行本文を読み出しません。

準備後にも送信設定と全条件のキュー再確認をI/O直前に実行。拒否は終端で、再参加／再購読で復活しません。表示は確認済みの確定件名と定型本文 `新しいメッセージがあります`、既存の本人認証を通る `/?messages=1`、宛先IDの安定タグ、既存Service Worker向けミリ秒期限です。TTLは元の残期限を秒へ切り捨て、残り1秒未満なら送信しません。通信取消は最大15秒と残リース／期限の短い方まで。認可からI/Oまでの競合を最小化しますが、完全解消とはしません。

## 結果と回復

- 成功は現在所有者の結果保存ができた場合だけProviderAccepted。端末受信／既読ではなく、保存を確認できない結果を成功とは報告しません。
- 明示400／401／403／413は終端失敗。
- 404／410は終端SubscriptionGone。現在の全紐付けがキューのダイジェストと一致する購読だけを削除し、送信中に置換された購読や別端末は残します。
- タイムアウト／ネットワーク／不明例外、408／5xxは保守的にAcceptanceUnknownで、自動再送しません。生の例外文／応答文を保存しません。
- 明示429はレート制限による未受付として回数／期限内で再試行します。Retry-Afterの秒数／HTTP日時を最小待機とし、ローカル15／30／60／120秒待機・合計5試行・元の期限も守ります。待機が期限以後なら早期再試行せず終端化。欠落／不正／複数ヘッダーはローカル待機とし、生ヘッダーは保存しません。
- 呼出し前で未送信と明確な失敗／未設定も回数／期限内の再試行対象です。外部呼出し後の親取消も独立した最大5秒の保存トークンでUnknownを記録してから取消を伝播。事前取消は占有しません。
- 結果保存失敗も保守的に扱い、占有期限切れはUnknownで自動再送不可。古いトークンで新試行／終端を上書きしません。外部への完全な一回性やUnknown照合APIは追加しません。

## 検証

`dotnet run --project tests/Sem.ManualNotificationPushDispatchChecks -c Release` は実合成SQLiteと外部通信なしで60項目を検証します。準備と直前確認、同時配信、応答分類、置換購読保持、ボックス非重複、TTL／期限／短時間取消、I/O前後の取消、不明の非再送、生エラーの非保存を含みます。うち2項目は実WebPush暗号化アダプターをメモリ内HTTPハンドラーへ接続し、平文を含まない暗号化、TTL、安定Topicを確認します。

全回帰、既存Service Worker試験、隔離した仮想パスキー／実Blazor受入、固定ソースCIは別証拠であり、実物端末受入ではありません。残りは上限付き走査／ワーカー接続、現在Cookie／Origin／CSRF／no-storeを備えた有効化画面／HTTP、実基盤／実機受信、配布承認です。
