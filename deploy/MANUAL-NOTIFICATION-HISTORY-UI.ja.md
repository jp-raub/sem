# 本人が作成した手動通知の履歴HTTP／画面

通知予定画面から `/events/{eventId}/manual-notification-history` へ進みます。対話開始時に現在ブラウザCookieで再認可し、明示操作だけで履歴を取得します。再読込で私的一覧や選択をブラウザ保存から復元しません。画面の生存期間は元の本人に固定し、アカウント切替後は画面を開き直します。

GET `manual-notification-history` は単一のイベント `id` と、現在Cookie本人と一致する単一 `actor` を要求します。続きは単一 `beforeAt` と単一 `beforeId` を必ず組で指定。Coreは毎ページで現在のアカウント／セッション・閲覧・管理者／作者範囲を再確認します。no-store、妥当なCSRF付きPOSTも拒否し、新しい書込操作はありません。

最新／次／前は待機前に旧一覧と選択状態を消去し、取得中の重複操作を禁止します。パラメータ変更／破棄で遅延結果を失効し、私的表示を消します。古くなったimportは代入前に解放します。取得失敗／不一致で旧一覧を出さず、403は全私的一覧を非表示。明示再認可でも古い行を復元しません。表示は取得時点のスナップショットで、常時の権限／配信監視ではありません。

本人件名はRazorで文字表示します。イベント・100件上限・小文字D形式ID・元の正の対象人数・Unix時刻・降順・要求カーソルより古いこと・続きのアンカー一致を検証します。前ページのカーソルは回線メモリだけ。新しい追加は最新再取得で確認し、複数ページ全体の固定スナップショットや全件数は保証しません。

行ごとの明示状態取得は既存PR53の独立した作者限定HTTPとPR54のticket検証を利用し、元の操作／人数／受付時刻を照合します。人数と端末保存件数、有効化／時間ゲートと個別適格性、配信基盤受付と端末受信／既読を区別。ポーリング・送信／再送・書込・ブラウザ保存・有効化変更・実Push・配布・マージは追加しません。

専用JSは単一GET・組カーソル・no-store／redirect拒否・不正入力・障害・自動再試行なし・保存／ログ／ポーリングなしを確認します。隔離実HTTPS／仮想ネイティブキー／Blazorは実HTTP本人／方式／カーソル／no-store、再読込後の再発見、文字表示、明示取得／重複阻止、選択状態、古い表示消去、403と再認可を確認します。100件超はCore SQLite試験であり、100件超の実ブラウザページ送りの証明ではありません。import中破棄は静的確認で、実ブラウザ故障注入の確認とはしません。CIは全.NET回帰も実行。Docker／DXP／物理端末／外部Pushは別工程です。

既存ワーカー登録と方針不在時の既定OFFは維持し、永続ONを強制OFFにしません。将来適用前の方針確認／明示停止は別承認で、このPRは本番適用承認ではありません。
