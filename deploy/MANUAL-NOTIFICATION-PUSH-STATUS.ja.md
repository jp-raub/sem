# 手動通知 Push 状態（Core 読み取り専用）

## 範囲と安全境界

この変更では、正規の小文字 D 形式リクエスト ID を指定する `CoreFoundationService.ReadEventManualNotificationPushStatusAsync` を追加します。イベント管理者が**自分自身の**受理済み手動通知操作を確認するための、読み取り専用 Core 機能です。他のイベント管理者や全体管理者であっても、別の作成者の操作は閲覧できません。各読み取りで有効なアカウント、メール確認、現在のセキュリティスタンプ、未失効セッションを再検証し、読み取りトランザクション内で現在の実効イベント閲覧権限と管理者権限を確認します。

この変更には HTTP ルート、API、UI、JavaScript、ワーカー、送信処理、監査書き込み、データベースマイグレーション、本番有効化の変更はありません。本番への適用や Push 有効化の許可を意味しません。親 PR の検証と GitHub 公開は別作業です。

## 返却値と解釈

集計のみの結果には、リクエスト／イベント ID、受理時点の宛先数と時刻、任意の元の失効時刻、ゲート区分、宛先単位の準備数、保存済みデバイス配信行数が含まれます。

- `NotAdmitted`: 元の受理時に admission がありません。後日の有効化で遡及追加されません。
- `Stopped`: 現在 Push が OFF、世代が一致しない、許可期間開始前、または保存 admission が不正です。全体世代値は返しません。
- `Expired`: 現在時刻が元の失効時刻以降です。
- `Eligible`: 元の admission が現在有効で、世代が一致し、未失効です。これは admission／有効化／時刻のゲートだけを示します。宛先やデバイスが現在の登録・アカウント・バインディング・最終送信検査を通ることは示しません。

準備数は不変の受理済み宛先スナップショットを分類します。準備済み宛先、準備行がない宛先、永続化された `NoEligibleDevices`、その他の既知の準備不可結果です。配信数は同じスナップショットに属する保存済みデバイス行をデバイス単位で数え、宛先数とは異なります。現在のデバイスを再検索したり、返信・受信箱履歴・後からの登録から宛先を追加したりしません。未知の準備結果／配信状態は、集計から黙って除外せずエラーとして拒否します。

`Accepted` はプロバイダーがリクエストを受理したとの報告に限られます。端末への到達、表示、既読、外部処理の exactly-once を証明しません。`Unknown` は結果不明のままです。結果は読み取り時点のスナップショットであり、返却後に変化し得ます。

結果に件名・本文、宛先の氏名／メール／ユーザー ID、デバイス ID／エンドポイント／鍵／フィンガープリント、セッション／セキュリティスタンプ情報、claim、activation 世代は含まれません。SQL はスカラー集計と操作／admission／activation の必要最小限の列だけを読み、宛先行やデバイス行をロードしません。

## 合成データでの検証

ローカル SDK を利用し、隔離された開発 worktree 内だけで実行します。

```sh
PATH=/data/dotnet:$PATH dotnet run --project tests/Sem.ManualNotificationPushStatusChecks -c Release
```

テストは一時的な合成 SQLite データベースに実マイグレーションを適用し、権限、admission／失効／停止、スナップショットとデバイス数の分離、シリアライズ時の秘匿、読み取りによる無変更、未知状態の拒否、SQLite 整合性と外部キーを確認します。合成データによるテストであり、本番検証ではありません。
