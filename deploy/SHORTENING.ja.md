# 短縮提案の計算基盤（段階実装）

英語版 `SHORTENING.md` を正本とし、この日本語版を同じ変更で更新する。

## 実装済み：アプリにはまだ接続しない

`ShorteningCalculator.Build` は副作用のない提案計算。短縮条件・見積・当初計画・
実績を保存しない。本段階には公開API、条件編集、承認処理はなく、「一回承認が
完成した」「配布済み機能」と扱わない。稼働処理は検証済みPR #14のままで、
追加するのは新しい計算コード・テスト・文書・専用CIのみ。

## 計算・保護条件

- 未指定／無効な条件は時間確保。曲の準備、進行の所要時間だけを許可できる。
  最短は0以上の整数秒で現在の見積以下。演奏と開場は短縮不可。
- 一つでも実績があればパート全体を保護する。準備開始済みの曲も対象外。
- 未開始・許可済みの対象をタイムテーブル順に検査。目標に届けば後続は変更せず、
  届かなければ各対象の下限まで提案する。
- 指定終了目標、未指定なら当初の最終終了を基準とする。変更前後の終了見込み、
  遅れ・実際の吸収可能量・残る遅れを表示できる結果を返す。
- 各候補で当日見積の連鎖を再計算し、曲の分繰上げを保持する。1秒の短縮が1分の
  回復となること、削っても繰上げ境界を越えず回復しないことを区別する。
  単に削った秒数を回復量としない。二分探索で目標を満たす最大の整数秒を求める。
- 当初計画・入力見積・実績・条件を変更しない。実績のUTCミリ秒、準備の継承null／
  明示0、演奏時間を保護する。提案の閲覧だけでは見積を書き込まない。

## 提案識別子と後続の承認

SHA-256識別子は計算版・イベントID・構造版／運営版・当初基準・全実績・明示見積・
条件に結びつく。列挙順だけの変更では変わらないよう正規化する。解決後の時間が
同じでも継承nullと明示値の切替では変わる。

**識別子は認可ではなく、承認処理でもない。** 後続の実装では以下を満たす。

1. 最新DBの本人・SecurityStamp・セッション失効・イベント管理権限・日本時間開催日を確認。
2. 単一の書込みトランザクションで最新版・条件・基準・実績・見積を取得して再計算。
3. 表示した識別子と両版を照合し、古い／変化した／対象のない案を拒否する。
   クライアントが送る短縮内容・時刻を正本にしない。
4. 再計算した対象だけを当日見積へ反映し、当初・実績を保持する。
5. 運営版・操作者・日時・要求指紋／結果・監査を一括保存。再送は現在の認可後に
   保存結果を返し、二重適用しない。同時承認は1件成功、他方を古い版として拒否する。

これらの承認処理、条件の永続化／移行、事前・当日の編集、管理者専用の常設提案、
一回承認、モバイル表示、実画面受入は**本段階では未実装**。

## 検証範囲

`dotnet run --project tests/Sem.ShorteningChecks -c Release` を実行する。
専用CIは既存進行・タイムテーブル・参加・業務・ストレージ安全性回帰、停止コピー、
警告をエラーとして扱うReleaseビルドと公開資産を検査する。
全体Docker／仮想パスキー／SMTP／実画面受入とは異なり、DXP・iOS・物理キーの確認を
意味しない。本番設定・鍵・ボリューム・イメージ・配布物・PRマージは変更しない。
後続連携に必要なユーザー仕様確認は現時点ではない。
