# 概要編集の人数上限・イベント配色

イベント一覧の「概要・管理者を編集」で、人数上限、イベント配色、表示モードを概要と一緒に保存できます。既存の参加管理・表示設定画面は引き続き使え、同じ保存先を参照します。新規マイグレーションはありません。

## 入力と保存

- アイコン／人数上限はモックv29に合わせ、スマートフォンでも2列です。配色／表示モードはヘッダー画像の後に置きます。
- 人数上限は0以上の整数、空欄は制限なしです。観覧を含む現在のユニーク参加人数より小さい上限にはできません。演奏枠の数ではありません。
- 配色と表示モードの「サイト設定を継承」はそれぞれ独立です。「端末設定に従う」は継承とは別の明示設定です。個人の表示設定がある場合は、従来どおり個人設定が優先します。
- 編集中の変更は下書きです。「保存」で概要と一括反映し、「取消」は下書きだけを破棄します。取消時に保存済みの設定へ書き戻す操作はしません。
- カタログ取得中や取得失敗時は保存できません。失敗したら取消後に編集を開き直します。別イベントの遅延読込結果は引き継ぎません。

## 競合と互換性

`POST /api/core/event` は、任意の `settings` オブジェクトを受け付けます。

```json
{
  "capacity": 20,
  "appearance": { "themeId": "rose", "mode": 2, "rowVersion": 1 }
}
```

これはリクエスト全体ではなく `settings` の値です。既存の概要フィールドとイベントの `rowVersion` も必要です。

- `settings` 未指定またはnullの旧リクエストは、現在の人数上限・配色・モード・テーマ版を変更しません。
- `settings` を指定すると `capacity` と `appearance` の両項目が必須です。`capacity:null` は制限解除、`appearance.themeId:null`／`mode:null` はそれぞれ継承です。`appearance` 自体をnullにする入力は拒否します。
- 概要のイベント版とテーマの独立した版を、同じSerializableトランザクションで照合します。参加管理・表示設定・別の概要編集で先に変更された場合は409となり、概要だけ・配色だけの部分保存はしません。
- 競合時は入力を残して結果を表示します。内容を控えるなどしてから取消し、最新の編集を開き直して確認・再入力します。競合を自動上書きしたり自動再送したりしません。
- 認証、live session、管理権限、Origin、CSRF、厳密なJSON検査は従来の境界を使用します。

## 手元での確認

1. CDの `observed_commit` を確認して対象版の更新完了後、管理可能なイベントの概要編集を開きます。
2. 上限・配色・表示モードを変更して取消し、開き直して元の値が残ることを確認します。
3. 同じ項目を保存し、概要を開き直して保存値を確認します。参加管理の上限と表示設定のイベント範囲にも同じ値があることを確認します。個人設定がある場合、見た目がイベント配色より優先されるのは正常です。
4. 上限を空欄、配色・表示モードを継承にして保存し、開き直して解除を確認します。参加者がいる場合、その人数を下回る上限は保存できないことも確認します。
5. 概要を編集中に別画面で同じイベントの配色または上限を保存し、元の概要で保存します。競合の通知と下書き保持を確認し、元の概要を取消して開き直すと別画面の値が保持されていることを確認します。
6. スマートフォン幅でアイコン／人数上限が2列、入力が画面外へはみ出さないことを確認します。

動作確認の承認はNotionの対象版ごとの依頼へ登録します。GitHub CI成功、GHCR公開、DXPへの実際の反映、手元受入は別の状態です。
