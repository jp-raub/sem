# GitHub版から協力ユーザーとの受入テストを始める

SEMは開発・受入テスト段階です。GitHub `main` のコードを正本とし、DXPへの展開は環境所有者が行います。別配布ソースや手修正を前提にしません。

## AIと環境所有者の分担

- AI: 実装、合成データでの自動検証、CI、GitHubへの反映、更新・復元手順、対象版を指定した検証依頼。
- 環境所有者: DXPへの更新、物理端末・認証器・実メール／Pushの確認、招待した協力者との受入テスト。
- 不具合は対象commit、操作、期待結果、実際の結果を記録します。Cookie、秘密鍵、招待URL、メール確認コードは貼らないでください。

## 更新前

1. 現在のcommit SHAと、使用しているComposeファイル・イメージ・永続ボリュームの場所を記録します。
2. [BACKUP.md](BACKUP.md)に従ってアプリを停止し、**データディレクトリ全体**をバックアップします。SQLiteだけでなくWAL、Data Protection鍵、秘密の画像等も一緒に保持します。バックアップ自身も秘密を含むのでGitHubに置きません。
3. INVの一意インデックス導入前の環境では、[重複検査手順](INV-003-DXP-PREFLIGHT.md)を実施します。非NULL `RequestId` の重複があれば移行は停止します。自動で既存行を削除・修復しません。
4. 空ディレクトリへの復元手順と、復元時に使う元イメージを確保します。新しいスキーマのDBを古いアプリにそのまま戻す方法をロールバック扱いしません。

## GitHubから展開

既存の環境変数・秘密ファイル・HTTPS設定・ネットワーク・**同じ永続ボリューム**を維持します。

```sh
git fetch origin main
git switch main
git pull --ff-only origin main
git rev-parse HEAD
# 既存の配置ガイドで使っているComposeファイルと設定を使用する
# docker compose ... build --pull
# docker compose ... up -d
```

具体的なCompose引数は[既存DXP配置ガイド](README.ja.md)を使用してください。ここで別名ボリュームを作ったり、`down -v`、データ初期化、アカウント／鍵のリセットを実施する必要はありません。ヘルスチェック成功に加え、更新前の利用者・イベント・参加登録を画面で照合します。

## 今回確認してほしい具体的な操作

Notionの承認依頼に記載した対象commitで、次を実施します。承認はその対象版・操作についてのみ扱います。

1. **認証・本人設定**: 管理者と一般利用者がそれぞれパスキーでログイン。プロフィール／アカウント導線から同じ設定画面の該当欄へ移動できる。追加キー登録・rename・削除取消・確定削除を確認し、最後のキーは残る。
2. **招待**: 一般利用者が依頼し管理者が承認／拒否する。判断コメントが依頼者に見える。所有者だけが招待リンクを取得し、招待先の別端末からメール確認・同意・パスキー登録で参加できる。
3. **イベント・参加**: 管理者が曲・パート・時刻表・受付フェーズ・設問を設定。一般利用者と管理者自身がmatrixの空き枠を選び、YOUR ENTRYで回答・登録する。他人の登録は担当名付きで見える。管理者操作欄は開いたときだけ操作可能。
4. **競合**: 別画面で時刻表を保存した後も未送信の枠・回答は残る。古い版の送信は競合として拒否され、明示的な最新状態取得後に再選択・再回答して保存できる。結果不明時は新しい操作として自動送信されない。
5. **コメント**: イベント左側でコメント本文が見える。「コメントのみ投稿」を開閉して入力が保持される。投稿しても参加枠・設問回答・観覧状態は送信されない。参加の下書きは残る。従来のコメント専用URLも使える。
6. **実通知・当日操作**: 許可した自分の端末・宛先へのメール／Push、受付・QR・当日進行を確認する。協力者の端末への送信は本人の同意を得て行う。
7. **継続保全**: 登録済みのプロフィール、イベント、割当、回答、コメントを控えて再起動し一致を確認。停止バックアップを別の隔離先へ復元して同じ状態と既存パスキーでのログインを確認する。共有環境のデータを試験のために消去しない。

## 開発側の自動検証

- `bash scripts/integration-checks.sh`: 全.NETスイート、合成UI、Docker非root・初期起動／再起動。
- `bash scripts/acceptance-browser-fixture.sh`: 空の一時環境とローカルSMTP・仮想認証器を作成し、複数ユーザー、matrix、単独コメント、データ入り全ディレクトリ復元を対話検証。既存の配置先を指定する機能はありません。空いているlocalhostの2525/18025/18080/18443を使用します。
- ブラウザー試験には.NET 10、Python 3、OpenSSL、Node、Playwright 1.56.1とChromiumが必要です。CIは依存を隔離して導入します。秘密を含むDB・メール・鍵・生ログは成果物として公開せず、検査名・件数のJSONのみ残します。

ローカル／CIの合成検証は、DXPの実ストレージ、公開HTTPS／proxy、物理認証器、実配送の受入を代替しません。
