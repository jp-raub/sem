# テーマの初回表示・画面遷移

## 対象と原因

`theme-appearance.js` は文書の `enhancedload` を購読していたが、Blazor の拡張遷移完了イベントは `window.Blazor.addEventListener` で受け取る。モジュールは拡張遷移で再実行されない。また、同一イベント内でも文書マージにより html の動的スタイルとモード属性が置き換わる場合がある。旧版は合成実ブラウザーで、最初の拡張遷移後のトークン復元検査に失敗した。利用者の端末・操作・全発生経路を独立観測したという意味ではない。

## 修正契約

- 初回の DOM 準備後に一度起動し、Blazor の拡張遷移完了で新しい文脈を取得・検証する。
- 同一文脈の文書マージでは検証済みの設定を再適用する。イベントが変われば古い設定を破棄し、新しいイベントの応答を待つ。
- リクエスト開始時のイベントを固定し、世代・現在のパスが一致しない古い応答を採用しない。
- BFCache からの復帰でも設定を再確認する。通常の初回 pageshow は重複読取の契機にしない。
- 設定の権威は認証済みサーバー応答。localStorage / sessionStorage へ個人設定を保存しない。401/403 時の私有状態消去、JSON とサイズ・色の検証、同一生成元・no-store を維持する。
- 自動処理は GET のみ。保存の自動再送、認証保護の緩和、DB migration、CD方式の変更は行わない。
- 通信失敗やタイムアウト時まで適用完了を保証するものではなく、成功応答前の一瞬の既定色表示を完全に無くす SSR 化は対象外。

## 回帰

`theme-lifecycle-browser-checks.cjs` は合成ローカル境界と実ブラウザーで、初回、文書マージ、初回イベント、イベント切替、遅延応答、401・認証後の復帰、明示ダーク、OS追従、BFCache、未送信入力保持、書込なし・runtime errorなしを検査する。

`theme-navigation-checks.cjs` は新規合成DBの実アプリと実Blazor拡張遷移を使い、文書がリロードされていないことも検査する。新規イベント2件だけに配色を設定し、既存の個人・サイト設定を変更しない。初回の表示設定ページのプレビュー・取消と非保存を含む。full候補にも必須で組み込み、一式バックアップ・復元と復元後利用可能性を維持する。

人への再確認は公開版の変更動作（通常の画面移動で配色がリロードなしに適用されること）だけに絞る。既存機能全体・同じSafariログイン・保留画像10MiBの試験は依頼しない。
