# テーマ選択 — 永続化とサービス層

英語版 `THEME-SELECTIONS.md` が正本。本カテゴリはストレージとコアサービス契約のみを追加し、HTTPエンドポイント、UI、CSS、デプロイは追加しない。

## 動作

- 外観は任意の永続化レイヤー3つで構成する：現在のアカウント、認可された `SessionEvent` 1件、サイト。パレットとモードはそれぞれ独立して「本人 → イベント → サイト」の順に継承する。何も選択されていない場合は、既存の `ThemeResolver` が永続カタログの `green` パレットと `System` モードを適用する。
- `ThemeId` または `Mode` がnullなら継承する。明示的な `System` モードは値として保存し、下位モードの継承を止める。書込みで受け付けるのはカタログIDだけで、任意の色値は保存しない。
- 読取りは現在認証中の操作者を使う。本人の選択、イベントコンテキスト指定時に認可されたイベントの選択、サイト選択、検証済みカタログ、解決済み外観、更新番号、現在のコンテキストに対する権限を返す。イベントの読取り／書込みには既存の現在フェーズ可視性・認可ヘルパーを使用する。イベント書込みはイベント管理者のみ、サイト書込みとカタログ削除は現在の全体管理者のみ。
- テーマ削除は未使用のカスタムテーマに限る。サービスは3つすべての選択スコープを確認し、RESTRICT外部キーが競合時の保護となる。組み込みテーマの削除はサービスとDBトリガーの双方で拒否し、既存の `BuiltIn` 不変トリガーも維持する。

## 移行とストレージ

移行 `20261015081000_AddThemeSelectionPreferences` で `UserThemePreferences`、`EventThemePreferences`、`SiteThemePreferences` を追加する。各テーブルはnullableなカタログ参照、`0`／`1`／`2` に制限したnullableなモード、0以上の競合制御 `RowVersion` を持つ。新規行は期待バージョン`0`で作成し、バージョン`1`から開始する。受理した更新ごとにバージョンを増やす。外部キーの削除動作は `RESTRICT`。

この移行は選択行を挿入せず、アカウント／イベント／サイトのテーマを選ばず、既存データもバックフィルしない。カタログは引き続き正本であり、この移行では再投入しない。Identity V3／パスキーのメタデータを保持する。

## デプロイ上の注意

本変更ではデプロイを実施していない。本永続化カテゴリを後続の承認済みリリースへ含める際は、次に従う。

1. スキーマ変更前に、既存手順でインスタンスを停止し、DBと鍵をバックアップする。
2. 通常のアプリケーション移行経路で移行を適用し、移行履歴と、認可されたサービス書込みまで3つの選択テーブルが空であることを確認する。
3. 選択値の保存後にEF `Down` でロールバックしない。整合性のあるバックアップから復旧するか、前進修正をデプロイする。
4. 本リリースはコアのみの機能として扱う。後続のHTTP／UIカテゴリがレビュー・デプロイされるまで、新しいルートやブラウザー操作はない。
