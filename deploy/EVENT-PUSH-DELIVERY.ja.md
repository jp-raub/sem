# イベントの自動Web Push配信

## 対象と有効化

開催前・曲準備の通知を実Web Push配信へ接続する。管理者ルールは引き続き既定OFF。本人が選ぶ任意タイムパートStart通知は今回の接続対象外で、破棄期限の方針は未決定。本人スイッチが保存されることを配信完了と解釈しない。

VAPIDの公開・秘密鍵の両方が必要。未設定は画面に別途表示し、未設定時はワーカーが送信／claimしない。公開ホスト名、VAPID鍵、Data Protection鍵と既存.envを維持する。本変更だけでDXPの稼働環境を変更・配布しない。

開催前は現在の正式な演奏参加者＋観覧者。曲準備は対象曲の演奏参加者のみ。全宛先は現在有効・メール確認済み・イベント閲覧可能であることが必要。端末購読だけでは閲覧権を得ない。自動フェーズはワーカーのキャッシュだけでなく現在時刻で再評価する。

承認済みの有効化・破棄条件は維持：ON／再ONで履歴をまとめて送らない。開催前は開場（なければ開催開始）、曲準備は予定＋10分と最新準備開始の早い方まで。準備／Start／End済みは対象外。直前実Start基準は有効化時の進行版より新しい必要がある。

## 購読の安全性と移行

移行 `20261013151643_AddEventPushDelivery` で購読のセキュリティスタンプ／セッション結び付けと端末別永続配信台帳を追加する。既存購読は保持するが、過去の安全な結び付けを推測して補完しない。**初回更新後、通知を受けたい端末ごとにログインして通知登録を一度やり直す。** 認証済みの現ユーザーのスタンプとセッションハッシュを保存する。鍵・資格情報・完全な購読URLをログやNotionへ貼らない。

登録後の通常のコンテナ再起動は購読を維持する。ログアウトは現在のセッションの購読を削除し、アカウント切替では旧キューを新所有者へ送らない。無効／メール未確認ユーザー、変更スタンプ、失効セッション、解除／置換済み端末は送信不可。従来のメッセージボックスPushも同じ結び付けを確認する。

エンドポイントはApple／Google／Mozillaの厳密な対応ホストのHTTPS:443のみ、資格情報／フラグメントなし。イベント配信のHTTPリダイレクトは無効。購読鍵・URL・セッション情報を配信台帳／本文／診断ログへコピーせず、台帳にはフィンガープリントを保存する。

## 永続化と送信直前確認

有効なイベントを一回最大20件、キーセットの巡回カーソルで処理し、不正イベントを分離する。イベント／論理通知／ユーザー／端末で一意。Acceptedを再開しない。送信側は一回最大20件を原子的にclaimし、2分のリースを保持、過渡障害は最大5回まで。停止プロセスの失効リースは復旧し、5回目の失効リースはFailed。

現対象者、現在の閲覧権、ユーザー／セッション／端末、ルール版、元データ、対象状態、期限を再読取。リース更新後、外部送信直前にすべて再確認する。残存期限の整数秒切捨てをTTLとし、タイムアウトは15秒と残存期限の小さい方。残り1秒未満は送らない。配信先404／410は変わっていない購読だけ削除し、同時再登録を消さない。

配信事業者受理後、Acceptedとユーザー論理通知ごとに一件の最小限のメッセージを保存。複数端末でもメッセージ重複は抑止し、汎用Push／SMTPを再帰起動しない。本文は一般的な説明・基準日時・安定タグ・認証付きタイムテーブルへの遷移で、曲名／イベント名／メール／設問回答を含めない。Service Workerはクリック先を同一オリジンの許可イベント経路に再検証し、従来のメッセージボックス経路も保持する。

## 保証範囲と限界

**Acceptedは配信事業者受理であり、端末受信／閲覧ではない。** 通常の再計算／再起動／競合claimでAcceptedを再送しない。ただし外部受理とローカル結果保存の間のクラッシュ／タイムアウトでは再試行で重複する可能性が残る。安定Topic／ブラウザータグは対応範囲で重複をまとめるが、厳密な一回配送は保証しない。受理済みPushは取り消せず、最終確認直後の状態変化との微小な競合も解消できない。

期限後の受信は古い操作を促す本文ではなく一般的な期限切れ案内を表示し、ブラウザーの可視Push要件を尊重する。ログアウト後は通知を再有効化する必要がある。OS制限、実VAPID、NPM経路、実端末への到着は別途配布後に確認する。

## 検証

```sh
dotnet run --project tests/Sem.EventPushDeliveryChecks -c Release
node scripts/event-push-service-worker-checks.cjs
```

本番暗号化／HTTP要求コードを偽HTTPハンドラーで検証し、実事業者／端末へは送らない。既存ルール試験はVAPID未設定と配信接続済みを区別する。全体CIは既存のデータ保持、SMTP、Docker、ネイティブキー、移行、対話Blazor試験を維持。CI成功だけでマージ／新配布／DXP操作を行わない。
