# 当日進行の予実・遅延表示

## 採用仕様と範囲

固定モック `9cf8b031258fa1c9afe9668f54e61f002c4bce17/mock` の TIME-COMPARISON / PROGRESS-EMPHASIS（v24〜25）を基準とする。基準mainは `0c9d04d2e88c292213a2de35db7e74564cb37811`。

- 曲・進行ごとのtbody、rowgroup見出しで名称を1回表示。曲は準備開始→演奏開始→演奏終了、進行は進行開始→終了、開場は受付開始→終了。当初計画／最新計画／実績を横比較し、未実績は「未記録」。日時跨ぎを省略せず、日本時間と秒を保持する。
- 準備m:ss→演奏m:ssの順。状態タグと当日見積を横並びにし、既存の禁止条件を保持。長い名称は省略しtitleに全文を保持する。記録点行は72px基本高で、内容を切り捨てず必要時に拡張する。
- 現在パートは6px左境界・背景・大きいタイトル。最新時刻の変更は太字・背景と読み上げ用変更ラベルで伝える。
- 遅延段階は正の差のみ：1分未満low、1分以上5分未満medium、5分以上high。各点の最新−当初を使う。現在の次の未記録点が最新時刻を超えた場合は、now−当初との大きい方を表示する。未来の回復や既に記録した点を理由に現在の遅れを隠さない。未来の回復点は通常色に戻す。
- 遅延時間の文章・現在点の警告・既存の状態表示を維持し、色だけに依存しない。秒は切上げ後に分秒へ分解するため、59.999秒が0秒表記にならない。light/darkの採用配色とforced-colorsの境界を明示する。
- PCでは予実表を既定表示。狭幅では記録操作を先にし、明示ボタン／キーボードで比較を展開。横スクロールはラベル付き比較領域内に閉じる。

## 保持する境界

ProgressPresentationは既存の不変DTOを読む表示専用ヘルパー。Coreの計算・レコード・サーバー時刻・API・DB/migration・認可・同時更新・短縮提案・演奏時間保護は変更しない。管理者の既存Summary計算を表示時刻で再評価するが、実績の記録や自動状態遷移は行わない。参加者DTOに管理用データを追加しない。単一記録ボタン、終了＋次開始の同時刻保存、当初計画保護、取消・二重操作の回帰を保持する。

デモ時計や本番時刻の上書きは追加しない。短縮／記録の結果不明や接続中切替等の既存境界を一般的な全面解消と宣言するものではない。

## 検証と公開の判定

表示ヘルパーの厳密な1分／5分境界・回復・実績の不変性を.NETで検証する。新規DBの実ブラウザーでは既存progress-checks（認可・記録・版競合・取消・見積・当初保護）を削除せず、グループ／行高／横並び／狭幅／キー操作／変更ラベルを加える。progress-emphasis-checksは実時計を使う合成イベントでlow/medium/high、現在と未来の区別、light/darkの実computed色を検証する。

必須integrationの既存timetable-editor-ui新規fixtureに追加し、既存full側の範囲、一式保全・復元・利用可能性、40分／30分枠を維持する。ローカル試行、固定headのCI、統合後main CI、実公開、公開URLの版＋readiness照合は別々に記録する。まだ確認していない段階を完了とはしない。

全UIの途中の個別承認依頼は作らない。画像10MiB保留と同じSafariログイン再試験不要を維持する。全モックUI完成・全レプリカ・全業務機能の検証完了をこの変更の成功だけで宣言しない。
