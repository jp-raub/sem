# イベントフェーズ：保持移行・自動切替・手動優先

正本は英語版 `EVENT-PHASES.md`。検証済みの本体基盤へ積み重ねる変更で、配布やDXP適用ではない。

## 実装範囲

- 実Phasesにイベント内の既定Hidden／Viewとカスタムフェーズを保持。新規はHiddenを有効・自動評価（Viewを明示した場合は手動）。既定は編集／削除不可。部分ユニークインデックスとトランザクションで有効なフェーズを1件に保つ。
- `20261012180718_AddEventPhases` はPhasesとManualPhaseOverrideを追加。既存正式イベントには既定2行を作り、以前のHidden／View、バージョン、管理者を保持して手動モードへ移行する。開催時刻が過ぎた旧非表示イベントを移行直後に公開しない。ユーザー／パスキー／招待／プロフィール／通知等と過去の移行は保持。既存PhaseKind列はHidden／Viewの互換表示キャッシュで、実際のフェーズ種別は有効Phases行が正本。
- `/events/{id}/phases` の実Blazor画面で追加・名前から編集パネル・削除候補・ラジオ選択・手動／自動を下書きに反映し、最後の保存で一括確定、取消しで未保存変更を捨てる。上限は登録曲数で-1無制限、0登録不可。実際の曲への申込みと上限適用は後続。名前は必須・100文字以内。日本時間入力、UTC保存、APIはネスト／プロパティ名の大小文字を含めタイムゾーンなし日時を拒否する。
- 手動優先は予定期間／イベント開始を越えて保持し、自動へ戻す保存まで切り替えない。自動は実サーバー時刻で、有効化<=現在かつ無効化未指定または無効化>現在のカスタムから開始が最も新しいもの、同時刻は保存した順序を選ぶ。それ以外は開催前Hidden、開始以後View。有効化未指定は手動用。両日時がある場合は無効化が有効化より後。ブラウザ指定の架空の評価時刻は実装しない。
- 起動時と15秒ごとの実ワーカーが自動イベントを評価。変更時だけ有効行・表示キャッシュ・バージョン・system監査を同一トランザクションで更新する。ミリ秒単位の切替保証ではない。管理者／概要の古い下書きは拒否し、同時更新を直列化する。
- 最新の有効性／メール確認／SecurityStamp／セッション失効／実ロールとイベント割当を毎回確認。カスタムの閲覧は管理権限への昇格ではない。管理計画は管理者だけ、一般のイベント一覧は現在のフェーズ要約だけを表示する。
- 削除する非有効カスタムは履歴用の墓標を保持し、IDを消去しない。選択中の有効フェーズは削除不可。別フェーズの選択と旧行の削除候補は一括保存可能。既定・削除済み・他イベントのIDへの偽装／復活を拒否する。曲／参加登録モデルはまだないため、その参照保持は後続実装で補う。本変更でフェーズ履歴は消さない。

## 検証と残範囲

PhaseChecksは保持移行、既定、権限、入力、時刻境界、重複期間／同時刻、手動／自動、競合、墓標／偽装、失効セッション、概要との整合、再起動とDB単一有効を検査。既存の基盤／ストレージ／追加証明／旧リセットも回帰する。

専用CIは固定旧版・固定基盤c951ffb・候補の3イメージを作り、合成データで旧版→基盤の既存実認証／画面試験、正式イベント作成済み基盤→フェーズ候補の保持移行、実Blazorの下書き／取消し／保存、実予約ワーカー、再起動とネイティブキー再ログインを検証する。SMTP／ユーザー／鍵は合成で、DXPではない。

イベント内パート定義／プリセットコピー、設問、曲・枠・申込み・回答・人数／曲数上限適用、完全なv33レイアウト／キーボードモーダル、リアルタイム共有、業務通知、認証復旧、PostgreSQL、運用バックアップは後続。フェーズ変更の自動メール／Pushはない。既存.env／各鍵／RP／プロキシ／元ボリュームの変更、配布、PRマージは実施しない。

**続行条件：** 試験合格後の定義／プリセット／設問は既存承認の範囲で確認不要で続行可能。新要件や矛盾が出た場合は実装前に具体的に提示する。各区切りで「続行可能」か「具体的なユーザー確認待ち」かを明記する。
