# 管理画面の編集保護

対象はイベントのフェーズ・曲・パート定義・設問、およびサービスのパートプリセットです。保存 API、認可、RowVersion、DB、CD の契約は変更しません。

## 二段階の下書き

- 編集欄の「下書きに反映」は画面内の下書きを更新するだけで、共有データへ保存しません。
- 「この編集を取消」、Escape、背景のクリックは同じ経路を使います。編集欄に変更がある場合は「編集を続ける」か「この編集だけ取り消す」を選びます。後者でも以前に画面の下書きへ反映した変更は残ります。
- 編集欄を開いただけで変更していなければ、そのまま閉じられます。
- 画面全体の「取消」は画面内の下書きを明示的に破棄します。編集中の欄は先に閉じてください。
- 共有されるのは最後の「保存」です。送信中は保存・取消・行編集を重複実行しません。競合で失敗した場合は下書きを保持します。認可拒否時は従来どおり保護情報を除去します。

## 移動と再読み込み

変更済みの下書き、送信中、または保存結果未確認の間は、サイト内の移動を止めて警告を表示します。勝手な保存・再送・下書き破棄はしません。変更がない場合や保存／全体取消の後は移動できます。

静的ルーターの拡張遷移も、文書内の通常リンク操作を捕捉して保護します。Navigation API があるブラウザーでは同一サイトの履歴移動も止めます。Navigation API がないブラウザーの同一文書内の履歴移動は、この追加ハンドラーでは捕捉できず、既存 NavigationLock とブラウザーの離脱確認の適用範囲に依存します。全ブラウザーでの履歴操作を自動検証済みとは扱いません。

再読み込みや外部への移動はブラウザー標準の離脱確認を使います。表示文言・表示可否はブラウザーに依存します。タブの強制終了・プロセス終了・端末故障に耐える永続的な下書き保存ではありません。保存結果不明の表示を成功へ読み替えません。

## モーダルの操作

ネイティブ dialog により背景操作とフォーカスを制限します。取消確認の初期フォーカスは「編集を続ける」です。閉じた後は元のボタンへ戻します。入力欄内から背景へドラッグしただけでは取消しません。ページを離れる際はリスナーを解除します。

## 検証

- `scripts/draft-navigation-guard-checks.mjs`：変更時だけ通常リンク・対応ブラウザーの履歴遷移を拒否し、別タブ・ダウンロード・外部リンク・ページ内リンクを妨げず、解除後のリスナーを残しません。
- `scripts/draft-edit-dialog-checks.mjs`：Escape、背景操作、ドラッグ、再同期、リスナー解除、フォーカス復帰。
- `SEM_ACCEPTANCE_FOCUS=edit-guard bash scripts/acceptance-browser-fixture.sh`：新規合成 DB と実ブラウザーで各画面の未変更時移動、下書き保持、編集欄だけの取消、全体取消、保存、競合、二重操作を確認します。サービスのプリセットは元へ戻し、共有 fixture を変更したままにしません。
- 通常の full fixture にも同じ検査を追加します。全体バックアップ・復元・利用可能性確認と既存の認可・保存回帰を維持します。

公開候補の検証と公開反映の最終結果は PR の固定 head／main の記録を参照してください。局所検証だけで full CI や公開成功とは扱いません。

## 手元の受入範囲

公開反映の自動照合後、変更された離脱警告と編集欄だけの取消に絞って依頼します。未変更のログインや登録機能全体、保留中の画像10MiBは対象外です。タイムテーブルの共通下書きへの統合は後続タスクです。
