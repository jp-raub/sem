# 本体基盤：サービス・プロフィール・イベント管理者

英語正本は `CORE-FOUNDATION.md`。本書は対応日本語版。本変更は最初の実業務基盤であり、UI MOCK v33全体の移植完了ではない。承認済みの認証／通知と旧イベントの明示的なリセットを土台とする。

## 実装範囲

- `/workspace` は実際のBlazor Server対話画面。パスキー認証は既存の `/` に残し、招待／通知テストから新基盤へ案内する。編集フォームは同時に1つ。サービス名／説明のプレビューは下書きで、保存まで共有設定は変わらず、取消は書き込まない。競合する古い下書きは自動上書きしない。
- サービス名は必須60、説明は任意80（HTML maxlengthと同じUTF-16単位）。有効・メール確認済みの現在の全体管理者だけが変更する。初回保存までは既存bootstrap側のサイト名を使用。保存名はSiteStates.Nameへ同期するが、初期設定制御項目は変更しない。SMTP送信元／表示名は別設定で、サービス名変更でSMTP・VAPID・.envを変更しない。
- 本人プロフィールは表示名60、読み80、対面呼称60、SNS（ラベル60・URL500・シリアライズ入力の技術的上限）。NFKC後、読みをひらがなに変換し、呼称はひらがな／カタカナ。SNSは資格情報を含まないHTTP/HTTPSだけを許可し、サーバーでは取得しない。リンクはnoopener／noreferrerで表示。基本プロフィールは有効・メール確認済みのログインメンバーへ公開し、メールは共有DTOに含めない。編集に対象ユーザーId項目はなく、未知JSON項目は拒否。全体管理者も他人のプロフィールは変更できない。
- アカウントは本人メールの読取専用と既存パスキー追加への案内。メール変更や復旧を動作するように見せるボタンは置かない。
- 正式SessionEventsのタイトル／概要／会場／必須開始／任意開場／お知らせと、基盤段階の非表示・閲覧公開。開場＝開始を許可し、開場未指定と区別する。UTCの正規ISO-8601 TEXTで保存。画面の日本時間を明示的に変換し、HTTP日時はオフセットまたはZを必須とする（JSON項目名の大文字小文字でも回避不可）。
- EventAdminsはEventId×UserIdの複合PKと外部キー、0名以上・複数名を許容。作成は全体管理者、担当管理者は自分のイベント概要と担当割当だけを編集できる。閲覧は管理権限ではなく、割当でIsAdminを変更しない。担当解除は古いブラウザの次の操作にも反映。正式Idは新規生成し、旧イベントIdを流用しない。
- サービス／プロフィール／イベントのRowVersionと、概要＋管理者一覧の同一トランザクション。成功時に操作者／対象付き監査を追加。書込みごとに有効状態、メール確認、セキュリティスタンプ、セッション失効と現在のDBロールを再検証し、署名済み・キャッシュ済みのロール主張だけに依存しない。
- ログアウトは現在の一意セッションのハッシュをRevokedAuthSessionsへ記録し、未完了の追加証明も取消す。HTTPと接続中のBlazor業務操作で失効を検査し、他セッションは失効しない。一意セッションのない旧ログイン状態は業務操作前に再ログインする。Origin付きBlazor通信の別Originを拒否し、HTTP変更操作には正確なOriginとCSRFも要求。非公開APIと業務画面HTMLはno-store。

## 移行と旧データ

`20261012162159_AddCoreFoundation` はServiceSettings、UserProfiles、SessionEvents、EventAdmins、RevokedAuthSessionsの5テーブルを追加する。Upで既存Identity／パスキー、初期設定、招待／使用数、メッセージ／配送／Push、証明、監査の行やテーブルを削除・変換しない。過去ユーザーにプロフィール値を捏造せず、未入力項目は空、未保存サービス設定は旧サイト名を参照する。

旧Eventsが残るDBは、基準取り込み／移行の書込み前に起動を拒否する。DB全体や鍵を消して回避しない。`LEGACY-EVENT-RESET.md` の停止コピー準備と明示的なイベント／参加リセットを使い、keysを含む元アーカイブ、元イメージ／元ボリュームを保持する。新しいバイナリに保守コマンドが残っていても対象は正確な旧スキーマ／履歴だけで、正式／将来DBを拒否しSessionEventsはリセットしない。

移行後の旧テストイベント作成／公開／参加APIは410、テスト画面の対応操作も除去する。代替受付経路にしない。新基盤DBを未対応の旧バイナリへ差替えたり、保持したいデータにEF Downを実行しない。復帰は従来の単一起動手順で未変更の元イメージ＋元ボリュームへ戻す。

本コード変更だけでPRマージ、配布、DXP更新、実データ削除は実施しない。.env、鍵、RPホスト名、ネットワーク別名も変更しない。DXPは固定した検証済みイメージ、停止中の最新DB＋鍵バックアップ、別コピーと公開先／aliasでの単一起動が必要。実Blazor画面では同じHTTPS Origin上のNPM／WebSocket転送も確認する。従来のPush受信確認はこの通信の証明ではない。プロキシ／ネットワークを自動変更しない。

## 検証と次の範囲

- `dotnet run --project tests/Sem.CoreChecks -c Release`：認可、正規化、メール非公開、イベント別権限、UTC／開場、古い／同時下書き、失効・スタンプ不一致、再起動保持。
- 既存ストレージ試験は旧イベントが残る場合のDB／履歴無変更の拒否も確認。追加証明、固定旧DBリセット、停止コピー準備の回帰も独立して維持。
- `SEM_CORE_FOUNDATION_CHECKS=1` はHTTPS／ネイティブ仮想認証器で、APIと実Blazorのプレビュー／取消、本人保存、イベント作成、競合／対象偽装／他イベント拒否、CSRF、日時、接続中画面のログアウト拒否、再ログインと担当解除を確認する。試験TLSプロキシはWebSocket転送を備え、実回線を通したBlazor操作として検証する。専用CIでDocker／新規DB／再起動／固定旧版移行も維持。

未完了：v33全レイアウト／ナビ／テーマ／トースト／ヘルプ、アイコン／アップロード、プロフィール設問と履歴、サービスのアカウント／ロール／プリセットと特権保護の全体、カスタムフェーズ／MaxPicks=-1／参加・回答・キャパ、曲と枠、タイム計画、当日進行、QR／受付、業務通知ルール／ダイジェスト／再予約。別の開いた業務画面への変更プッシュは未実装で、再取得で共有状態を読み込む。監査詳細／操作者種別／時刻モデルの正規化、認証期限／復旧／メール変更／全セッション失効、購読ライフサイクル、PostgreSQL、正式運用移行、鍵保存時暗号化、日次バックアップ／世代保持も別タスク。今回の現在セッションのログアウト失効は認証リセット／復旧の完全実装ではない。

APIと画面／アセットのレート制限枠は分離し、既存のIP単位・毎分60 API／180画面の上限を維持する。最初のリクエストで両方の制限値が決まる状態を解消。基盤のブラウザ受入試験は全コンテキストのAPI通信を間隔制御し、制限を緩めない。
