# 公開回答集計 — 第1段階

英語版 PUBLIC-ANSWERS.md を正本とし、本書は対応する日本語版です。

## 今回の範囲

認証付き `GET /api/core/public-answers?id=<event>` と実Blazor画面
`/events/<event>/public-answers` を追加。業務基盤と参加登録画面から移動できます。
対象は現在の使用中・未削除・Public=true の設問だけ。管理用設問APIは引き続き
管理者専用です。今回は読みやすい表による第1段階であり、モックv33のグラフや
イベント統合画面の完成ではありません。コメント・QR受付・インポートは未追加。

毎回、有効性・メール確認・SecurityStamp・セッション失効・現在の閲覧権を確認し、
参加登録と同じ手動／自動フェーズ判定を使います。管理者はHiddenを確認できますが、
設問の非公開条件は回避できません。公開設定と回答は同じトランザクションの読取
スナップショットを使います。応答はno-store、公開集計へのPOSTは拒否します。
再取得・ページ移動・権限エラー時に画面の旧結果を消去します。
自動更新ではありません。変更は次の再取得／再読込で反映され、既に見られた内容や
保存された応答を後から回収する保証はありません。

## 件数の意味

- イベント・設問に保存されている空でない回答が対象。参加解除後に残った回答も含み、
  現在の演奏／観覧登録を条件にしません。承認済みモックと同じ母集団で、回答を消しません。
- YesNoは前後の空白を除いた正確なYES／NOだけ。YESとNOの2群、分母はその合計。
  null・空白・不正な旧値は対象外です。
- TextでPublicのみON：回答数・表示名だけ。本文なしの1群でvalueはnull。
  非公開本文をDBの応答用射影やDOMに取り込みません。
- Textで両方ON：前後の空白を除いた本文を完全一致で集約。大文字小文字を区別し、
  勝手なかな・大文字小文字正規化や省略を行いません。各群の件数と回答者を表示します。
- 使用停止・削除・非公開の設問は管理者でも出力しません。PublicTextだけでは公開不可。
- 回答者は不透明なユーザーIDと表示名だけ。メール・連絡先・セッション・回答日時・
  認証情報を出しません。停止済みユーザーの保存回答も歴史上の件数には残りますが、
  ログインやプロフィール閲覧権を付与しません。

参加入力画面と応答DTOで、回答数／回答者・YES／NOの公開、独立した本文公開を明示。
変更したのは応答レコードであり、参加登録の要求形式・指紋・再送識別・部分成功・
監査・業務通知の登録は変更しません。

質問・本文・表示名を通常のRazorテキストとしてエスケープし、HTMLとして挿入しません。
キャプション・列見出し付きの表を小画面でも利用できます。横比率／本文別グラフ、
hover／タップ／フォーカスの回答者表示、タイムテーブルとコメントの間への統合は残作業。

## 保存・検証・運用境界

既存の回答／公開設定を利用し、新規移行・スキーマ変更は不要です。

```bash
dotnet run --project tests/Sem.PublicAnswerChecks -c Release
# 隔離SMTP／ブラウザー環境の実キー・移行・実Blazorハーネスで使用
SEM_PUBLIC_ANSWER_CHECKS=1 node scripts/e2e.cjs
```

実画面フラグは既存のストレージ更新ハーネス内で動作します。
SEM_STORAGE_UPGRADE_COMMANDなしでフラグだけを渡してもモジュールは実行されません。
public-answer-summary.ymlの全体Docker検証に追加し、既存の全回帰も維持します。

合成データのみを使用し、実NAS・実メール宛先・Push事業者には接続しません。
PRマージ・新配布・DXPイメージ／データ／.env／鍵／公開ホスト名の変更はありません。

## 次の段階：コメント

承認済み条件：前後空白除去後3文字以上、新しい順、削除は管理者のみで本人も自己削除不可。
一般ユーザーの投稿は開催日の終わり（Asia/Tokyo、翌日0時を含まない）まで、管理者は
終了後も可能。コメントのみの投稿に演奏／観覧登録は不要です。参加登録とまとめて
投稿する経路では、モックの部分成功と安全な再送処理を保持します。
以上は次の実装条件の記録であり、このPRで実装したものではありません。

後続のイベントコメント実装で上記条件を実装します。実装範囲と検証は EVENT-COMMENTS.ja.md を参照してください。
