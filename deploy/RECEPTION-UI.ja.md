# 受付UI：検索・読取記録・手動確認

採用モック `9cf8b031258fa1c9afe9668f54e61f002c4bce17` の `checkin-reception.js/css` を基準に、既存の受付機能を実データへ接続した表示に揃える。模擬QR読取、モック認証、デモ時計は移植しない。

## 変更した表示

- 参加登録者の表示名／読みの検索と、表示名／読み・申込状況・受付・直近QR読取り・受付完了の記録・操作の6列表。狭幅では表だけを横スクロールする。曲名とプロフィールへの既存リンクは保持する。
- 手動受付を中央のnative dialogへ移動。本人・申込みと必要な受付対応を確認し、明示して確定する。受付済みの対象は同じ入口から記録と取消を確認できる。二重受付を作らない。
- 未送信メモ等がある場合の閉じる／Escapeは破棄を確認する。背景タップは破棄しない。処理中・結果不明・QR処理の排他中は閉じる処理そのものを拒否し、同じ操作IDによる明示確認を維持する。
- キーボードのTab周回と、一覧再取得でボタンが置換された後の対象者へのフォーカス復帰。破棄時は所有する旧モーダルだけを閉じる。
- QR読取と受付完了／取消しの履歴は、それぞれ開閉できる区画へ整理。読取表は縦横、受付履歴は縦にスクロールでき、既存の最大100件・前後ページ・対象者フィルターを保持する。

## 最終読取を正しく表示する条件

一覧の最終QR読取は、履歴APIの先頭100件から推測しない。同じ認可済みDBトランザクションで、表示中の現在の参加登録者（最大100人）について、そのイベントの全読取から `At` 降順・同時刻は `Id` 降順の先頭をSQL内で一意に選ぶ。取得結果は対象者ごとに最大1件で、別イベントや登録外の対象の記録を投影しない。担当者の表示名と日時だけを追加し、秘密コード、メール、私的回答、受付メモを一覧へ追加しない。

QRを読み取っただけでは受付済みにならない。受付取消でも読取履歴は削除しない。受付済み／未受付の分母は検索一致件数ではなく現在のユニーク参加登録者全体とする。検索の先頭100人と、全対象者／全履歴を混同しない。

## 維持する境界

- 現在のイベント管理権限と有効セッション、公開名簿との情報分離を維持する。認証主体・セッション・イベントが変われば古い画面状態と入力を破棄し、古い非同期結果を再適用しない。
- 確定・取消のAPI、版競合、明示確認、同一操作IDの冪等性、結果不明時の自動再送禁止を変更しない。QRのカメラ・貼付・期限・本人・再発行確認は既存の独立機能のまま。
- DBモデル・migration・CD方式は変更しない。公開候補の一式保全復元と利用可能性確認、必須CIを省かない。
- 表示情報は取得時点の記録で、実際の出席・全端末・全レプリカの証明ではない。

## 検証の分離

採用モックと旧版の390／1440pxの実描画で、中央モーダルとインライン確認欄の差を確認した。旧版の受付・確定・取消回帰と画像取得は通過したが、同じ試行の後続プロフィール設定検査は、先行のプロフィールfixtureが表示名を変更した組合せで失敗した。この試行を全件成功へ流用しない。修正版は受付専用の新規fixtureと、既存fullの独立した新規fixtureで検証する。

サービス回帰は最終読取の同時刻・別イベント・先頭100件より古い対象・登録外・公開名簿への非公開・読取と受付の分離を含む。ブラウザー回帰は320×568／390×844／768×1024／1440×900／844×390、ライト／ダークで中央座標・画面内・入力保持、取消確認・Escape・背景・Tab・フォーカス復帰を確認し、既存の手動受付・取消・QR・履歴回帰を維持する。処理中／結果不明の閉じる禁止はモジュール検査と実ハンドラーの契約検査でも維持する。

個別のユーザー承認依頼は作らず、全採用UIを優先する。ヘッダー画像10MiBの保留と、改善済みSafariログインの再試験不要は維持する。実行結果と対象版はPRの検証記録を正本とする。
