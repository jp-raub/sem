# 手動通知の作成・確認画面と受付保護

英語正本：`MANUAL-NOTIFICATION-UI.md`。

## 対象範囲

原子的な送信受付基盤の後続。既存の通知タブ／予定画面から、管理者限定の `/events/{id}/manual-notification` へ接続し、POST限定Core APIを2本追加する。現在の認証・アカウント／セッション／SecurityStamp・DB管理権限・イベント実効閲覧、操作IDの不変条件、ボックス／未稼働送信待ち／監査の原子的保存は既存Coreを使う。追加移行・Pushワーカー・SMTP呼出し・配布・本番適用・マージは追加しない。

最終操作は**メッセージボックスへの保存**。受付済みは端末受信・既読ではない。人物ごとのPush待ちは未稼働のままで、実配信前に期限方針を決める。自動イベントPushや予定台帳は変更しない。

## HTTP保護

`manual-notification-preview` は件名／本文、`manual-notification-accept` は既存の厳格な受付DTOを受ける。POST・設定Origin一致・CSRF・通常ログイン・DBの現在管理権限が必要で、GETは405。全応答と私的画面HTMLはno-store。下書きをURLへ出さずJSON本文で渡す。イベントの`id`に加え、画面を開いた本人の`actor`ヒントと現在の認証本人が一致しなければ拒否する。これは認可トークンではなく、Coreも独立して現在権限を再確認する。

プレビューは正規化済み文字・イベント情報・現在のユニーク対象人数・比較値・定型Push表示だけを返し、宛先ID／プロフィール／回答／購読を返さない。受付は操作ID／人数／日時／再取得区分だけ。画面のエラーへ例外や件名／本文を出さない。

## 明示操作と不明結果

1. 件名1〜80・本文1〜2000 UTF-16長。正規化は既存サーバーが正とする。プレビューは明示操作で、保存しない。
2. 正規化済み件名／本文・対象人数を確認し、別チェック後に保存。入力変更でプレビューと承認を失効する。
3. 最初のawait前に小文字D形式GUIDと承認済み要求を固定。処理中・結果不明では連打・入力変更・取消・別送信を防ぐ。
4. 一致する有効な受付結果だけで元の人数／日時を表示し入力を消す。別通知は明示的な新規作成から始める。
5. 初回の明確な400／403／409は最新プレビューへ戻し、権限拒否では私的入力欄を隠す。通信断・タイムアウト・壊れた／不一致の成功・429／5xxは**不明結果**として自動再送せず、同じ固定要求だけを明示再試行する。不明後の拒否は過去のコミットを否定しないため操作IDを破棄しない。権限再確認で本人をすり替えない。

未送信入力／プレビュー・処理中・結果不明は内部遷移を拒否する。未送信取消はローカル入力と承認だけを消し、保存済みメッセージを変更しない。再読込／外部遷移にはブラウザ標準警告を使うが、ユーザーの離脱選択や強制終了は防げない。下書き／固定要求は回線メモリだけで、localStorage／sessionStorage・認証状態ファイルへ保存しない。再読込／回線消失後のUI自動復旧は保証しない。Coreの永続再取得には同じIDと要求が必要で、画面破棄でDB受付が消えることはない。

破棄／世代確認・無関係な親描画で保留を消さない制御、権限拒否後の入力非表示、文字エスケープ・改行・キーボードフォーカス・44px操作域・PC／390pxに対応する。合成実画面試験は実物モバイル／DXP受入とは別。

## 検証

- `dotnet run --project tests/Sem.ManualNotificationComposerChecks -c Release`：明示確認・二重操作防止・固定再試行・明確拒否と不明結果・一致する受付・未送信取消の状態試験。
- `node scripts/manual-notification-transport-checks.mjs`：1回だけの明示通信・CSRF／no-store・URLへの本文不出力・各障害・自動再送／保存／背景ループなし。
- `bash scripts/manual-notification-ui-check.sh`：隔離publish／新規DB、localhost HTTPS／SMTP、実仮想ネイティブパスキーによる全体管理者／一般参加者を使う。現在の観覧者・権限／CSRF／本人一致・実Blazorの文字表示／タブ保護、**コミット後の応答喪失**、拒否後の私的入力非表示と権限再確認、同一要求再取得でボックス1件だけを確認する。終了時に一時DB／鍵／プロセスを片付ける。.NET 10・Python・OpenSSL・Node・Playwright／Chromiumとlocalhost 18080／18443／18025／2525の空きを要する。`SEM_CHROMIUM`でブラウザ実行ファイルを指定可能。ログイン状態ファイルを作らない。

専用CIはRelease警告エラー化・全.NET回帰・関連JS回帰・隔離ネイティブ受入を行う。Docker／旧イメージ更新・DXP・実物端末／カメラ・手動Push実配信の証拠ではない。実績はPR／ダッシュボードに記録し、テスト追加だけを合格扱いにしない。
