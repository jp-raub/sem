# イベントPush通知ルールの明示的有効化

[英語正本](EVENT-PUSH-RULES.md)に対応する日本語版。

## 今回の境界

承認済みの開催前・曲準備の2種だけに、現在の管理者専用スイッチと送信可否／破棄期限の読取判定を追加する。**DeliveryConnectedはfalseのまま。ONでもまだPush予約・実送信はしない。** 本人向け任意パート開始の希望は別枠。宛先・端末・メッセージ・配信キューは作成しない。Eligibleは送信要求受理／端末受信／閲覧ではない。

次の配信処理は、現在の権限・送信対象・有効購読を確認し、端末単位の永続的な重複抑止／占有を持つ必要がある。送信直前にルール版・最新元データ・破棄期限を再確認し、古い処理を取消し、失効済み紐付けを無効化する。ロック画面の情報最小化と、認証を通る同一オリジン遷移も必要。ルール画面だけで配信要件の完成やDXP適用としない。

## 有効化と破棄期限

既定はOFF・版0で書込みなし。OFF→ON時にミリ秒単位の有効化日時と現在の進行版を保存し、版／監査を同じトランザクションで確定する。同じONの保存は無変更で、有効化境界を動かさない。OFFは版を保持し、有効化項目を空にする。再ONは新しい境界を保存し、既存の期限到来済み通知／実績を履歴通知として流さない。再起動後も境界を保持する。

送信予定日時は、有効化日時より**厳密に後**であることが必要。直前パートの実Start基準は、捕捉した進行版より新しいことも必要。実績待ちは時刻を推測せず、対象開始済みは不可。将来予定と期限到来を区別し、破棄期限ちょうどから送信不可とする。

- 開催前：開場、なければ開催開始まで。
- 曲準備：送信予定＋10分と最新準備開始予定の早い方まで。実準備／演奏開始・終了済みは対象外。最大日時近傍でも算術を範囲内に保つ。
- ルール・元データ・破棄期限が不正／未確定なら送信不可。読取だけでキューや台帳を書き換えない。

移行 `20261013134737_AddEventPushRules` はイベント×種別主キー、イベント外部キー、種別／版／有効化Null条件と楽観的版管理を追加する。既存PR21の認証・本人設定・保護データ・配信キューは保持する。

## 操作経路

no-store GETと認証・Origin・CSRF保護付きPOST `/api/core/event-push-rules?id=<eventId>`。入力は必須のkind・enabled・version・eventVersionで、任意の対象者IDを受け付けない。現在の全体／担当管理者権限、有効アカウント、SecurityStamp／セッション、最新イベント版を再確認する。古いタブ・OFF/ONの版戻りを拒否し、不正な元データでは有効化しない。設定と監査は失敗時に一緒にロールバックする。

InteractiveServer `/events/{EventId}/event-push-rules` は管理者の通知予定から遷移。スイッチ・日本時間の有効化／破棄期限・接続完了前の操作無効化・未送信の明示を持つ。権限／読取失敗は古い表示を消す。英語正本と日本語を同じ変更で更新。DXP／.env／鍵／ボリューム／公開ホスト名・新配布・マージは変更しない。
