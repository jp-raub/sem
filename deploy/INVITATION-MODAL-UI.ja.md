# 招待管理のカード表示と操作モーダル

## 採用基準と実装範囲

基点main `6a9fcf4e5e4fce814067e099cc09c61c79d8ba95`。採用済み固定モック `9cf8b031258fa1c9afe9668f54e61f002c4bce17/mock` のv32–33招待UIを基準とする。

- 依頼一覧を上段のカード、本人向けの発行済み招待を下段のカードにする。読み取りAPIが返した情報を削らず、依頼理由・人数・日数・状態・判断者・コメントを表示する。内部IDは識別情報として保持する。
- 全体管理者には直接発行と判断、一般ユーザーには発行依頼の入口を表示する。管理者向け招待台帳は詳細列と横スクロールを残す。
- 発行／依頼の入口ボタン、対象依頼の判断、対象招待の緊急失効から中央のnative dialogを開く。人数／日数は2列、内容が長い・画面が低い場合はモーダル内部をスクロールする。
- Escape／背景／閉じるで未送信入力と確認を破棄する。破棄でサーバーへ送信しない。処理中は閉じられない。対象行の再構築後も元の操作ボタンへフォーカスを戻す。
- 依頼成功時は閉じて一覧へ戻る。直接発行成功時は一時リンクを同じモーダルへ表示し、閉じたとき消去する。

## 維持する保護

既存 `invitation-management.js` が唯一の操作主体。追加のdialogアダプターは表示／focusだけで、HTTP・保存・再送を実行しない。

- 認証・全体管理者／所有者・Origin／CSRF・strict DTO・入力上限・operation generationの検査は維持。
- チェックによる明示確認、入力変更後の再確認、結果不明時の書込ロックと明示的な読取再確認を維持する。モーダルで不明状態を覆わず閉じてページ側にロック理由と再読込を表示する。
- 一覧に秘密リンクを含めない。本人取得／直接発行の一時欄だけに表示。ページ離脱・ログイン状態変更・破棄でも消去する。モックの公開リンク常設・認証迂回を移植しない。
- 失効は既存APIの独立した即時操作。通常編集の保存／取消へ合流しない。登録枠消費、DB／migration、メール／Pushの処理は変更しない。
- 50件ページングとAPI最大ページ制約、旧記録で人物・目的・方式不明の明示を保つ。

## 検証・限界

既存transportの合成回帰をそのまま維持。dialogの権限別入口、busy／unknown、フォーカス、破棄を合成検査し、新規DBの実アプリで依頼→判断→本人リンク取得→即時失効、直接発行、狭幅／明暗、結果不明の再送禁止を検証する。独立したintegration fixtureに追加し、既存full fixtureと保全復元は削らない。

サービス管理ページへの台帳埋込み、登録／復旧等の別画面、全採用UIの照合完了をこの変更だけで宣言しない。実リンクの外部共有、実Push／メール配信、物理認証器は試験しない。全UI完成までは個別承認依頼なし。画像10MiBは保留。
