# 手動通知Pushの方針と永続的な受付対象印

## 範囲

2026-10-14に承認された3点を反映する基盤です。

- Push期限は元の受付から正確に600秒。ボックスの保存／既読とは独立。
- 現在の有効な演奏割当・観覧登録がない人は、その後のPush対象外。保存済みボックスは保持。
- Push有効化前に受付済みの通知は、後から配信しない。

本変更には**本番の有効化更新機能・HTTP経路・DI／ワーカー登録・端末別配信キュー・外部送信接続はありません**。有効化状態がなければOFF。画面の配信未接続表示は維持します。DB直接編集で有効にしないでください。試験内の状態設定は合成フィクスチャ専用で、運用手順ではありません。

## 永続的な境界

追加移行 `AddManualNotificationPushAdmission` は `ManualNotificationPushActivations` と `ManualNotificationPushAdmissions` の作成だけです。有効化初期値の投入・既存表再作成・過去受付への印付け・宛先Pending変更・既存ボックス／自動Push／SMTP／設定／認証情報／鍵の変更はしません。

Coreの新規受付時に有効な世代がONの場合だけ、受付対象印を操作・確定済み宛先・ボックス・監査と同じトランザクションで保存します。印には有効化世代、元の受付秒、受付＋600秒の期限を固定。同一再試行では印を追加・更新せず、元の結果だけ返します。有効化と同じ秒の古い受付も対象へ復活しません。

将来の監査付き有効化更新は受付と直列化し、再有効化ごとに単調増加する新しい世代を使う必要があります。OFFは受付済み対象も抑止し、別世代は古い通知を復活させません。今回その更新機能は実装せず、有効化操作が完成したとは扱いません。

## 観測専用の方針チェック

`ManualNotificationPushPolicy.ReadAsync` は1つの読取トランザクション・時刻で、受付印・現在世代・期限・確定宛先／ボックス本人・現在のアカウント／実効閲覧／参加登録／端末紐付け／stamp／セッションを確認します。既存事実チェックを共有し、PR43単体の結果契約は変えません。

期限ちょうどでExpired、受付より過去への時計逆行は拒否。元の印なしはNotAdmitted、無効／別世代はDisabled／ActivationChanged、現在参加なしはNoLongerRegistered。全条件通過もEligibleForStaging・DispatchConnected=falseにすぎず、**後の外部送信の認可ではありません**。結果に秘密情報・本文を含めず、読取でメッセージを変更・削除しません。将来のワーカーでは拒否の永続的な抑止と送信直前の全条件再確認が必要です。一度終端抑止したジョブは再参加で復活させません。

## 検証と残作業

`dotnet run --project tests/Sem.ManualNotificationPushPolicyChecks -c Release` は実移行した合成SQLiteで39項目を検証します。データ入り旧スキーマ更新・既定OFF・同秒境界・同一再試行・正確な期限・世代変更・解除後のボックス保持・後発宛先の非追加・現在のアカウント／stamp／セッション／閲覧／紐付け・独立した実読取専用接続での再取得・故障注入時の全体ロールバック・制約・整合性／外部キー・取消を含みます。既存回帰も別途必要です。

残りは監査付き有効化更新、宛先／端末別永続準備、占有／リース、回数制限付き再試行と外部結果不明、直前確認、定型Pushと本人認証付きボックス遷移、実Push／実機受入です。Docker／DXP／配布／マージ完了を意味しません。
