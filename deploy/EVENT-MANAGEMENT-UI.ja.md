# イベント詳細の管理UI統合

基準は main `145d614a0e078b9f5ab3de69a437d475fce59ae5` と採用モック `9cf8b031258fa1c9afe9668f54e61f002c4bce17/mock`。全UIの完成宣言ではなく、イベント詳細の管理情報順と実操作の接続を対象とする。

## 表示と保存の境界

管理者の詳細ページでは、フェーズ → タイムテーブル → 公開回答 → 観覧 → コメント → 設問 → 管理者 → WebPush → 監査の順に置き、先頭に各区画への実アンカーを置く。公開回答・観覧・コメントは従来の閲覧権限を維持し、通常参加者に管理編集欄や管理者名・監査を追加公開しない。

- フェーズ・設問は既存の実編集部品を埋め込む。編集欄内の反映、画面内の下書き、最終保存を区別する。中央取消確認・未保存移動保護と独立した版照合を維持する。
- 曲・進行の共通下書きは前版の契約を維持する。フェーズ・設問・概要まで一括保存に変更しない。
- 管理者区画は表示名と既存の「概要・管理者」編集欄への入口である。独立した管理者だけの保存APIや全管理設定の共通保存ではない。
- WebPushは従来どおり項目単位の即時保存であることを表示する。他の下書きを保存・取消しない。Push登録・許可要求・実送信は追加しない。
- 既存の専用URL `/events/{id}/phases`、`questions`、`event-push-rules` と既存サービスAPIを維持する。

## イベント監査

新規GET `/api/core/event-audit?id={eventId}` は毎回DB上の有効利用者・現セッション・イベント管理権限を検証する。POSTは不可。100件を表示し、取得上限は1〜200件。時刻とIDで安定した降順とする。5列の表は区画内でスクロールできる。

イベントIDそのものを対象にする既知の操作、イベントに属するコメント／削除済みコメント操作・参加操作・進行操作・短縮操作への明示的な関連、既知のイベント複合キーだけを対象にする。汎用のID部分一致検索はしない。本文・メール・秘密値・任意の監査詳細は投影せず、表示名・操作種別と固定説明だけを返す。削除済みコメントは本文を復元せず既存の操作記録の帰属だけを使う。

これはサービス全体の監査をイベント管理者へ開くものではない。認証・復旧の監査は含めず、受付・取込等の詳細履歴は各専用画面に残る。存在しない詳細本文を表示できるかのように装わない。

## 非同期と下書き

親のイベント・本人／stamp／session・世代と、各操作の世代を照合する。同じ対象の親再描画では編集欄を初期化しない。対象や本人の変更、破棄、後発処理の発生後に古い応答が届いても採用しない。保存直前にも本人情報を再確認し、変更を検知した旧下書きを送信しない。管理権限失効を検知した際は親も再読込し、全管理区画を除去する。別の管理区画・参加入力・コメント下書きを勝手に送信・消去しない。

## 検証と残件

ライフサイクル境界、監査の帰属と権限、実アプリでの順序・導線・競合・下書き保持・狭幅／明暗・権限失効・旧URLを自動回帰する。必須integrationの既存 `timetable-editor-ui` fixtureに管理UI検査を直列追加する。フル受入・保全復元・ジョブ時間枠を削減しない。ローカル専用focusは `SEM_ACCEPTANCE_FOCUS=event-management-ui`。

DB/migration、認証方式、配信方式は変更しない。公開候補では従来の一式バックアップ・復元・利用可能性、必須CI、公開後の新鮮な版＋readiness照合を行う。結果は対象PR／commitの記録で判定する。失敗試行を成功へ流用しない。

全モックUIは引き続き作業中。パート定義の並べ替え、当日進行、その他画面の最終状態照合等は別の残件として維持する。全UIが揃うまで通常の個別承認依頼は作らず、採用モックと自動回帰を基準に進める。画像10MiBは個別保留、同じSafariログイン再試験は不要。
