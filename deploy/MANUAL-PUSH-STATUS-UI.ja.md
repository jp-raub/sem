# 手動Pushの操作別状態表示

## 読取専用の接続

GET `/api/core/manual-notification-push-status` はイベントId・固定本人Id・受付済み小文字D形式の操作Idを各1つ要求します。現在Cookie本人の一致に加え、Coreで現在のセッション／stamp／アカウント／イベント管理と操作作者を独立確認します。POST拒否・全応答no-store。送信・再送・準備・ボックス／監査の変更をしません。

受付結果に明示的な状態取得ボタンを追加します。初回自動取得・定期取得・自動再試行はありません。取得前に古い状態を消し、不一致／失敗時も古い数を再利用しません。取得中は新しい操作への切替を無効にし、メモリ内ticket／世代で新規操作・破棄・画面終了後の遅延結果を拒否します。403では受付結果と状態を隠し、元の本人の現認可後も古い状態を自動復元しません。ブラウザ保存・認証状態ファイル・状態本文のログなし。

元の対象人数と準備区分は人、キュー状態の件数は端末です。その他の準備未成立には期限切れ・非admission・拒否などを含み、単一の抑止理由ではありません。admissionゲートは現在の全体世代／期限だけで、個別端末の現送信可否ではありません。保存済みPending／Claimedは整理前のまま残る場合があります。配信基盤への受付は端末受信／既読ではなく、Unknownは自動再送しません。再取得で元の期限を延長しません。内容・対象者／端末Id・紐付け秘密情報を返しません。

専用表示状態／通信試験と実HTTP／仮想パスキー／Blazorで、私的読取・方式／本人／引数・明示取得・保留取得・不一致・権限拒否／再認可・PC／スマホを検証します。最終ソースの合格数／CIは完了後に記録します。実画面ラッパーはホストPush鍵を明示的に空にし、実Push先を使いません。

本番有効化・DXP/.env／実データ／鍵／公開適用・追加移行・新配布・マージなし。この画面は現在の作成画面に保持している本人の受付操作だけで、履歴一覧や他の作者の操作表示ではありません。本番適用／実機受入は別工程です。
