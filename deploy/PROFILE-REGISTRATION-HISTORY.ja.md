# プロフィール登録履歴（Core 読取専用）

`CoreFoundationService.ReadProfileRegistrationHistoryAsync(ClaimsPrincipal principal, string userId, CancellationToken ct)` は、有効かつメール確認済みの対象メンバーについて、現在の登録状態を最小限返します。呼出側には有効な現在の認証セッションが必要です。応答には対象ユーザーIDと、閲覧可能なイベントのID・名称・開催日時、観覧状態、現在登録中の曲／パートの名称・分類を含みます。メールアドレス、プロフィール回答、トークン、端末情報、管理者の識別情報は含みません。

## 対象範囲と閲覧権限

- 完全な履歴ではなく、直近に限定した表示です。開催日時の降順、イベントIDの昇順で同時刻を決定的に並べ、候補イベントを最大100件選びます。この「最大100件」は**閲覧権限で絞り込む前**に適用されます。非公開または設定不備の候補が含まれると、返却件数は100件未満になり、古い閲覧可能な登録があっても0件になる場合があります。
- その候補枠を確定してから、呼出ユーザーの現在の `ParticipantEvent` 権限（現在の認証セッション、有効フェーズがちょうど1件であること、手動／自動判定後の有効フェーズ、現在のイベント管理者／全体管理者権限）を適用します。対象者がイベント管理者でも、呼出ユーザーへの閲覧権限にはなりません。閲覧不可または設定不備の候補は、そのID・名称・件数・合計・その他メタデータを返さず省きます。
- 応答に合計件数、`hasMore`、カーソル、非公開候補数はありません。完全な登録履歴として表示してはいけません。
- 返す登録は現在の状態のみです。解除済み登録・削除済み曲／定義・受付履歴・過去のフェーズ状態は再構成しません。現在の `SongParts.AssignedUserId` と、削除されていない曲・イベント内パート定義の結合、および現在の観覧登録を使用します。
- 同一イベントで観覧と演奏の両方に登録している場合、イベント項目は1件にまとめ、`Spectator: true` と現在のパート一覧を返します。

## 読取専用の保証

データベースの読取トランザクションと追跡なしの射影を使用します。`SaveChanges`、古いフェーズキャッシュの修復、自動フェーズの観測、登録や監査状態の変更は行いません。一般の参加情報DTOは使わず、無関係な個人回答を読み出しません。

追加範囲はCore APIと専用の合成SQLite検査のみです。HTTPエンドポイント、UI、スキーマ、マイグレーションは追加しません。
