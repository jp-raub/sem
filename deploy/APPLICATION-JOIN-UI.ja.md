# アプリケーション招待登録UI

`/join` は、既存の招待登録・パスキー登録フローへ入る匿名の静的SSRページです。招待の発行は行わず、確認リンクを画面に表示せず、既存のパスキー登録完了APIが成功するまで通常のログインセッションを作成しません。

## 利用フロー

1. 招待コード、表示名、メールアドレスを入力し、明示的に送信します。`POST /api/join/register` へ `{ invite, name, email }` のみを送ります。`{ message }` 応答は確認メールの送信依頼として表示し、トークンやメール内のリンクは画面に出しません。
2. メールの確認リンクは `/join#token=...` を開きます。最初の通信より前に `history.replaceState` でアドレスバーからクエリとフラグメントを除去します。トークンはメモリ内だけに保持し、ユーザーが確認ボタンを押した場合に限り、`POST /api/join/confirm` へ `{ token }` のみを送ります。
3. 確認API成功後に `GET /api/status` を読みます。未ログインかつ `enrolling: true` の場合にだけ次の手順を表示します。登録対象の利用者情報は受け取らず、表示もしません。現在のブラウザーの登録確認セッションを続けることをチェックボックスで確認し、別のボタンを押すまでパスキーオプション取得や `navigator.credentials.create` は行いません。
4. `POST /api/passkey-options` には `{}` を送り、応答の `PublicKeyCredentialCreationOptions` をそのままネイティブAPIへ渡します。明示的なパスキー登録後、`POST /api/passkey-complete` へ `{ credential: "<serialized credential JSON>" }` のみを送ります。通常ログインCookieの発行は既存サーバーAPIが行います。後続の状態確認で現在のブラウザーがログイン済みと確認できたときだけ `/workspace` へ移動します。

## 安全性と失敗時の動作

- フォームはSSR時点で無効化し、入力には `name` 属性を付けません。スクリプト未読込時に通常のフォーム送信で入力値を送れません。初期化失敗は画面に示し、操作を無効のままにします。
- `/auth` からの登録リンクは拡張ナビゲーションを無効にし、ページ全体を読み込み直します。`join.js` は一度だけ実行するdeferスクリプトです。
- APIパスは固定の同一オリジンURLを使用し、`credentials: same-origin`、`mode: same-origin`、`cache: no-store`、`redirect: error` を指定します。各POSTの前に `/api/csrf` から新しいトークンを取得して `X-CSRF-TOKEN` に設定します。同一オリジンの `Origin` ヘッダーはブラウザーが付与し、サーバー側検証を最終的な境界とします。
- CSRF取得後、各POSTの直前に `/api/status` を再確認します。匿名・登録確認・ログイン済みの状態区分が変化していれば送信を中止します。status契約には登録対象を識別する値がないため、登録確認Cookie間の利用者同一性まではUIで判定できません。サーバー側のCookie紐付けを最終境界とし、保留中の利用者を表示・断定しません。
- 招待登録・確認のリクエスト本文は4KiB、パスキー登録完了は64KiBまでです。応答は解析前に上限を確認し、JSON形式とfatal UTF-8デコードを要求します。通信タイムアウトは25秒です。
- トークンやパスキー応答をストレージ、クエリ文字列、ログ、表示テキストに書き込みません。通信前にフラグメント値を除去します。DOM更新にHTMLパーサーを使わず、テキストと入力値のみを設定します。
- POST結果が不明な場合は書込み操作をロックします。読み取り専用の状態確認はできますが、その結果から過去の要求の成功や対象者を推定したり、フォームを再有効化したり、自動再送したりしません。`enrolling` だけでは登録対象者を識別できないため、現在のブラウザーセッションを続ける意図を利用者が明示確認します。
- ログイン済みの場合はワークスペースへの案内を表示し、登録・確認操作を停止します。最終的な認可と登録確認Cookieの紐付けはサーバーが担います。
- ページ破棄時は通信と、対応ブラウザーではネイティブパスキー要求を中断します。非同期処理の各段階でページ・操作が現在のものかを確認してから画面更新や次の要求を行います。

## 対象外

このUIでは招待発行・承認、メール配信、再送、トークン表示、アカウント復旧、パスワード認証、新しい登録スキーマは実装しません。既存の `/api/status`、`/api/csrf`、`/api/passkey-options`、`/api/passkey-complete` と招待登録APIを利用します。

`scripts/application-join-ui-checks.mjs` は合成環境で契約と画面ライフサイクルを検査します。サーバーAPIの統合検証や実ブラウザー／認証器による受け入れ確認の代替ではありません。
