# UI MOCK v8：イベントページの入力と表示

2026-10-11の依頼と確認回答を反映。

- 日時のテキスト表示はyyyy/MM/dd HH:mmのまま、カレンダーボタンを追加。対応ブラウザではネイティブ日時メニューを開き、未対応では入力を表示する代替動作。
- 時刻はネイティブの上下キー操作。時間は選択している時/分/秒の位置に応じた上下キー増減。既存の時間検証と曲長1秒以上は維持。
- 編集開始ボタンをイベント概要エリアへ移動。
- 新規イベントの既定準備時間を10分。未設定のデモ初期値2分も10分へ更新するが、タイムテーブル設定の操作履歴がある既存イベントの明示設定は維持。曲別の明示準備時間も維持。
- 通常表示の登録済み枠はクリックでプロフィールを開き、ホバー表示と情報アイコンは削除。登録状態を変更しない。管理編集中の登録解除操作は維持。
- 進行行を通常の配色にし、パート用のセルボタン/プレースホルダーは表示しない。編集用操作は維持。
- 所要時間列に「準備 m:ss」「曲 m:ss」を改行表示。長い曲も総分数でm:ss表示。
- 準備開始と演奏開始だけ次の分へ切り上げる（13:02:35→13:03:00）。演奏終了・進行の開始/終了は丸めない。準備開始を切り上げ、指定準備時間を加えた時点を再度切り上げて演奏開始とする。繰上げ待機時間は終了予定超過判定に含めるが、所要時間欄は指定の準備時間/曲長を表示する。
- 回答者表示はPCではホバー中のみ、カーソル付近に固定配置する。表/グラフのクリップを避け、グラフより前面に表示。ユーザー回答に基づきタッチ端末ではタップ表示と外側タップによる閉鎖を維持。
- イベントの演奏パート定義パネルを削除。データ、既存の枠と新規曲のイベント内パート選択は維持。サービス側プリセットはそのまま。
