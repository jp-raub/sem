# イベント概要：管理者読取と入力UIの接続

要件の正本はNotion「要件・整合性・テスト観点」。本書は採用mockの製品接続範囲の記録で、要件を追加しない。UI基準 `9cf8b031258fa1c9afe9668f54e61f002c4bce17` と171資産は変更しない。

## 採用する構造

- 現在の管理対象イベントのタイムテーブルに「✎ 編集モードへ」。編集barのキャンセルで通常表示へ戻り、hero内の「概要を編集」から中央のnative dialogを開く。
- `modal-overview.js` 単体でなく、最終 `site-ui.js` の平坦化・短縮ラベルを採用する。8行（title / dates / place / identity / description / announcement / header / theme）、日付・場所・アイコンと上限・配色の2列ペア、概要の入力形式／原文／表示欄を保持する。
- 開場／開始は明示Asia/Tokyoの入力値へ変換する。保存済み原文と形式をそのまま表示し、サニタイズ済みHTMLから原文を逆生成しない。
- 必須／任意と日本語JSONの説明を使う。入力はdialog内のメモリだけで、端末ストレージへ保存しない。
- キャンセル・×・Escape・背景は入力を破棄し、概要入口へフォーカスを返す。Tab／Shift+Tabはdialog内で循環する。移動・再読み込み・失効では入力と編集modeを破棄する。

## 読取境界

`GET /api/ui/events/{id}/overview/editor` は既存read rate limit・no-store下の読取のみ。query／body／Transfer-Encodingを拒否し、GET以外に保存処理を持たない。

同一SQLite読取snapshot内で、現セッション・本人の有効性／メール確認／パスキー・現DBの全体管理者／対象EventAdmins・実効フェーズを確認する。claimのロールだけでは許可しない。原文は通常の公開プロフィールやイベント一覧へ追加しない。非担当・不明対象は同じ404、失効は401。不整合は422で、未知の形式や欠損テーマを既定値へ書き換えない。

最小DTOは本人と対象ID、概要項目・安全化済み保存概要・画像有無、イベント層だけの色／modeと選択候補ID／名前。個人設定による上書きをしない。DBのRowVersion、鍵、メール、秘密トークン、画像バイナリを含めない。文字数上限は読取資源の防護で、将来の保存仕様の確定を意味しない。

開く直前に再取得し、本人・対象・厳密なDTO項目を照合する。閉じた後の遅延応答は表示しない。取得失敗・余分なDTO・本人／対象相違では古い管理入力を消し、再読込を案内する。401は本人表示も消す。定期読取は開いた未送信入力を勝手に描き直さない。

## 未接続を明示する範囲

この段階は入力・取消だけ。**下書き反映、変更の保存、画像アップロード／削除、配色プレビュー、入力中のHTML／Markdownプレビューは未接続**で、確定ボタンと画像操作を無効化する。直接submitでも処理を進めない。保存済み概要だけを既存サーバーの共通無害化境界で描画し、原文をブラウザーのinnerHTMLへ挿入しない。入力変更後は保存済みの表示を消して未接続と表示する。

編集barは将来の編集範囲の入口であり、他の管理タブ・曲や進行・設問・配色管理全体を実装済みとしない。全体取消に未保存変更の確定はなく、下書きへの反映を偽装しない。

公開既定demo、実volume未接触、README削除を維持する。公開版照合の成功は実業務保存や物理端末・全レプリカの受入を代用しない。

## 検証

- `tests/Sem.EventOverview.Checks`：新規合成DBの現担当／全体権限・剥奪・失効・原文と形式・共通無害化・明示UTC・イベント層・秘密値なし・DB/WAL不変。modeの範囲と欠損テーマは既存DB制約でも拒否される。
- `scripts/event-overview-browser.cjs`：実製品＋localhost合成HTTPSで実担当の原文取得、非担当404、query400／非GET405、採用最終フォームの4幅×明暗の構造・寸法、入力・取消・focus・遅延・失敗・余分なDTO・401、保存／画像操作0、保存DTO不変。
- ローカルの集中実行は `SEM_FOCUSED_OVERVIEW=1`。既定の全接続回帰にも同じ検査を含める。実Originをテストへハードコードしない。
- 初期の新規unit fixtureは必須Viewフェーズ不足、次の不正mode fixtureは既存DB制約で拒否されて失敗。両方を訂正して新規DBから再実行する。最初のブラウザー再入場helperも同一hashで編集modeを維持する状態を考慮しておらず失敗し、状態に応じた再入場へ訂正。失敗試行は成功へ流用しない。最初のビルドには共通無害化クラスのnamespace import不足があり、追加して再ビルドする。
