# 招待管理者の参照と未送信入力UI

## 採用範囲

要件の正本はNotion「要件・整合性・テスト観点」F03・U05／U06。固定mock `9cf8b031258fa1c9afe9668f54e61f002c4bce17` の全ラッパー適用後を基準にする。171資産は変更せず、実認証モードのProductUIへ接続する。

- `#/invitations/manage`：全体管理者には全体の依頼、Pendingだけの判断入口、直接発行入口を表示する。一般／イベント限定管理者の既存本人参照は維持する。
- `#/admin/users`：採用位置の招待リンク一覧を9列・横スクロール可能なtable-wrapへ接続する。ユーザー・権限・プリセット・テーマの管理は未接続と明記する。
- 判断・直接発行・緊急失効：採用native dialog、短いラベル・必須／任意、理由500文字、人数1〜5・日数1〜7・既定1、選択・入力・取消・起点フォーカス復帰を接続する。

**確定保存・通知・秘密リンク表示は未接続**。入力が有効でもsubmitは無効で、フォームsubmitを直接発火しても保存・成功表示・自動閉鎖へ進まない。緊急失効の業務上の即時性は説明するが、この段階で実行したようには見せない。キャンセル／×／Escape／背景は未送信入力を破棄する。

## 認可と参照契約

GET `/api/ui/administration/invitations` と `/page/{page}`。現在のセッション・stamp・失効と、DBの `Users.IsAdmin` を同じSQLite read snapshotで確認する。ServiceAdmin claimやクライアントのisAdminだけでは許可しない。匿名／無効認証401、現DB非管理者403。不正ページ・query・body400、非GET405。既存180読取／分・no-storeを維持する。

依頼と発行記録をそれぞれ100件、Created／ID降順、101件目は続き判定だけへ使用する。発行台帳の行は秘密コードではなくopaque IDで対応させ、TokenHash・ProtectedTokenをSELECTしない。メール、セキュリティstamp、秘密キーや受信者一覧も返さない。明示Direct／Requestまたは実在する関連依頼を方式に使い、旧方式・欠損人物／日時／上限は不明とする。旧記録の発行者を現在の管理者から補完しない。

入力を開く直前にも同じ現在権限と当該ページを再取得し、判断済み・失効済みの対象は操作入力へ移さない。対象がページから消えた場合も同様。取得失敗・別人DTO・未知／秘密列混入・権限喪失では古い全体記録を消し、正常0件や操作完了へ変換しない。モーダル閉鎖後の遅延応答を再生しない。

## 検証の区別

- 専用.NET回帰：合成DBの実管理者、現権限剥奪、偽claim、多重claim、stamp・session・失効、最小列、100件ページング、欠損記録、DB／WAL不変。
- 実HTTPS：実非管理者の403・query／page／非GET拒否。管理者の表示比較には合成admin DTOを使用し、これを実権限付与の証拠にはしない。
- 最終mockと320／390／768／1440px×明暗の区画・モーダル主要スタイル・短いラベル／必須任意を比較。取消4方式、フォーカス循環、理由制約、未接続確定、取得失敗・不正DTO・401・判断済み対象・遅延・正常0件、POST等0を検査する。
- CI既定の全接続回帰を維持し、専用区画で合成プロセスを再起動する。同じDB／鍵／Cookieと各起動時の検証済み保全を保持する。読取制限を緩めず、429なし・クライアント例外0・外部通信0を検査する。

初回の専用検査は、合成招待の空TokenHash重複を既存unique制約が拒否した。各合成値を一意に修正して新規DBから再実行し、その失敗を製品成功へ流用しない。

## 残り

秘密リンク復号／表示、発行・許可／拒否・失効の保存、CSRF／競合／監査／通知、招待の消費と登録フローは後続。公開既定demo・実volume未接触を維持する。全サービス管理・全UI・実機受入の完了ではない。
