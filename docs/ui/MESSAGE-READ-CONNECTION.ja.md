# 本人メッセージ参照UI

F11・U02・U05・D04・T02に対応する読取接続。固定mockの最終 `message-box` / `inbox-message` / `message-title` と本人宛本文dialogを使い、固定171資産は変更しない。

## APIと保護

- `GET /api/ui/messages/unread`：現在本人の全件未読数だけ。表示ページ内の件数を未読総数として扱わない。
- `GET /api/ui/messages`、`GET /api/ui/messages/page/{page}`：0始まり、最大100件、新しいCreated→ID降順、続きの有無。本文をSELECT／DTOへ含めない。
- `GET /api/ui/messages/{id}`：現在本人宛の1件を認可してから本文を返す。別人のIDと欠損は同じ404。
- それぞれ本人・stamp・session・有効性を同一SQLite読取snapshotで再確認する。別ユーザーの指定、query、本文、書込は受け付けない。DB／WAL・監査・cacheを変更しない。
- 全入口はno-store。件名・本文はHTMLとして実行しない。件名2000文字、本文65536文字、一覧ID128文字の安全上限、JSON1Mi文字の上限を設ける。100件の題名や長文を小さい認証DTO用の64Ki上限で誤拒否しない。
- 保存モデル・migration・過去記録は変更しない。Messageに明示的な遷移先の列がないため、本文／件名から関連イベントを推測したリンクを作らない。Createdの既定0は日時不明、範囲外時刻は422で報告し、別の時刻を補完しない。

## 画面

常設通知入口に保存済み未読数を表示する。取得失敗時は0でなく「—」と未確認の説明にし、他の画面は利用できる。ボックスは本人宛の保存済み件名・時刻・既読状態だけを表示し、100件単位で古い記録へ移動できる。

件名を開くと同じ本人文脈で個別の本文を取得する。本文は改行を保持した文字列で、閲覧専用の閉じる1つ。別対象DTO・余計な本文を含む一覧・重複ID等を拒否する。画面移動／失効／失敗で旧本文・件名・未読表示を消し、遅延結果を新しい文脈へ適用しない。

## mockとの意図した差分

- 開くだけで既読にする模擬保存は移植しない。既読保存は未接続と説明し、未読数や保存状態を偽って変えない。
- 古い記録の不明な遷移先を補完しないため、mockのイベントリンクを無条件に表示しない。
- 全履歴へ到達するための100件ページング、日時不明・読込・失敗・失効・未接続の説明は製品固有の補助UI。

送信・既読保存・通知許可要求・Push登録／配信は後続。全UI完成、実認証の公開有効化、ユーザー実機受入ではない。

## 検証

合成DBで本人限定・ID直接参照・全件未読／ページ件数の分離・100件超・時刻欠損／異常・失効・DB／WAL不変を検証する。合成製品HTTPSで最終mockとの4幅×明暗比較、本文エスケープ・改行、ページ復帰、失敗／401／別人／不正DTO／遅延、未読数失敗の非0扱いを検査する。集中実行は全接続回帰と区別して記録する。

最終候補の全接続回帰は449検査・111秒を実測した。従来の製品UI工程2分では余裕が9秒しかないため、この工程だけ上限3分へ調整する。job全体8分、他工程の個別上限、必須assertionと失敗診断は維持し、検査省略や失敗無視は追加しない。実行時間自体を意図的に引き延ばす変更ではない。
