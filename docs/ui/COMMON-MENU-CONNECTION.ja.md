# 共通メニューの採用順・補助設定と未接続経路

## 実装対象

実認証モードの共通メニューを固定mockの最終項目・文言・順へ揃える。全体管理者だけ「サービス管理」を先頭へ追加し、共通項目は「イベント一覧ページ → プロフィール管理 → アカウント管理 → 通知管理 → 招待管理 → ログアウト」とする。表示設定は補助区画へ残す。デモのロール切替・リセットは持ち込まないため、補助見出しも「表示設定」とする。

常設の未読入口は別に維持する。実際に接続済みの一覧・プロフィール・アカウント・メッセージ・表示設定の操作はそのまま使う。採用drawerのDOM・既存共通CSSを使用し、固定171資産は変更しない。

## 閉じる動作

開くと最初の項目へフォーカスする。項目のクリック（現在と同じURLも含む）、外側クリックで閉じる。Escapeで閉じた場合はメニューボタンへフォーカスを戻す。aria-controls／aria-expandedを一致させる。ログアウト・認証消失時は私有入口と補助設定を消し、ログインだけを表示する。

## 未接続経路の境界

以前は未認識の認証済みURLが一覧へフォールバックした。通知管理、旧端末通知設定、招待管理、サービス管理は、それぞれの名前と未接続範囲を表示し、一覧・データ0件・設定無効・操作成功へ置き換えない。不明URLも別の「ページを表示できません」へ分ける。

この段階では当該画面全体の実装完了とはしない。ブラウザー許可要求、Push購読／送信、招待発行／承認／失効、権限変更等を追加しない。権限表示に使う最小セッションのisAdminはUIの入口だけであり、将来の業務APIで必要なサーバー認可の代用にはならない。実非管理者のサービス管理直接URLは拒否表示とする。公開default demo・実volume保護・root README削除は維持する。

## 検証

固定mockの最終メニューと一般／全体管理者表示の項目順・文言、320／390／768／1440px×ライト／ダークのdrawer・リンク・ログアウト・補助区画の主要スタイルを比較する。合成isAdmin DTOの変更は表示検査だけに限定し、実権限を付与した証拠と扱わない。元の実セッションへ戻して非管理者の直接URL拒否も検査する。

同URL項目・外側操作・Escapeとフォーカス復帰、旧URL・不明URL、未接続経路で業務データを取得しないこと、通知許可要求・POST等が0件であることを確認する。既存の全接続回帰を省略せず、共通メニューは同じ合成DB・鍵・Cookieを引き継ぐ第4プロセス区画で実行する。4回すべての起動保全、読取429なし、クライアント例外0、外部通信0をassertし、製品制限・必須CI・時間上限を緩めない。

## 後続の招待管理接続

上の「招待管理は未接続経路」という記述は共通メニュー接続時点の履歴。その後、[本人の招待記録と入力](INVITATION-READ-EDITOR.ja.md)を接続したため、招待管理だけは本人限定の実参照へ進む。通知設定・サービス管理等の未接続案内は維持する。送信・秘密URL・全体管理者の判断等まで接続済みとはしない。


## 通知入口の参照接続追補

通知管理と旧端末通知URLは[通知参照UI](NOTIFICATION-READ-CONNECTION.ja.md)へ接続済み。それ以前の未接続経路の記述は当時の境界。現在ブラウザーの許可参照と本人の保存済み開始通知だけであり、購読・保存・配信や管理者編集の完了とはしない。
