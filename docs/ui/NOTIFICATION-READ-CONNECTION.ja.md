# 通知管理の参照UIと現在ブラウザーの境界

## 正本と対象

要件の正本F11・U07・D04・N01に従う、mock起点の通知管理の参照段階。旧PR115の機能・受入完了を新構成へ転用しない。固定mock `9cf8b031258fa1c9afe9668f54e61f002c4bce17` の最終通知ページ（`preview-page`・breadcrumb・通知許可panelと通知事項panel）と共通CSSを使う。171資産は変更せず、明示実認証モードの独立アダプターへ接続する。

`#/notifications/manage` と旧 `#/account/notifications` は同じ入口。現在ブラウザーの許可と、本人の閲覧可能なイベント別開始通知を同じ画面へ置く。固定mockの模擬購読・拒否デモ・テストボタンは製品へ入れない。現在ブラウザー段階を全端末一覧・遠隔解除へ拡大しない。

## サーバー参照契約

- GET `/api/ui/notifications`：現在本人、サイト名、閲覧可能なイベントのID・題名だけ。初期選択なし。
- GET `/api/ui/events/{id}/notifications`：同じ索引と、認可対象の現在行（開場／曲／進行）のID・題名・種類・予定開始・本人の保存ON/OFF、2つの既存管理ルールの設定有無・有効状態。
- 毎回同じSQLite deferred snapshotで現セッション・失効・現全体／担当権限・有効フェーズを再確認。Hiddenの担当外と欠落は同じ404。参加登録・演奏担当の有無は本人設定の参照条件にしない。
- SQLの時点で本人×対象イベント×現行へ絞り、削除／欠落行への過去希望・他人の希望を除く。存在しない本人設定は仕様どおりOFF。管理ルールは未設定（OFF）と保存無効を分ける。
- 購読・endpoint・P256dh・Auth・セッションhash・予約・配信記録・私的回答・メールは読まない／返さない。GET body/queryと非GET拒否、no-store、既存180読取/分を維持する。DB書込み・migration変更はない。
- 予定は既存の秒単位・開場導出・準備継承の計算器を共用。予定開始を実Startや配信実績と呼ばない。構造不整合や上限超過は422で止め、空／OFFへ偽装しない。

## 現在ブラウザーの表示

`Notification.permission` とAPIの有無だけを読み、未選択・許可・拒否・非対応を区別する。購読の本人への紐付けや配信可能性は「未確認」。許可済みだけで登録済み／到達可能としない。

画面の参照・イベント選択・再取得で許可要求、Service Worker登録、購読の取得／生成、通知送信を行わない。登録・再紐付け・解除は未接続として無効。iOSホーム画面・対応環境・拒否時の案内と遅延／未達の説明を維持する。

## 未接続操作と状態

- 本人の開始通知ON/OFFは現在値の無効checkboxで参照。保存・配信・管理者ルール編集は未接続として説明する。管理入口も現担当にだけ表示して無効化する。
- イベント選択は本人に束縛した画面メモリだけ。再読込では未選択に戻し、認証・共有データをlocalStorageへ入れない。
- 7.5秒の既存再取得を利用。失敗／401／権限喪失／不正DTOでは旧表示を消す。遷移後の遅延結果や別人・別対象DTOを適用しない。取得失敗を0件やOFFへ変換しない。
- 任意通知の本文・対象／任意ルールの内容・送信予約等がこのDTOで実装されたとはしない。2つの既存管理ルールの有効状態参照は、最終的な管理定義UI全体の代用ではない。

## 検証

`scripts/notification-browser.cjs` を既存の製品合成HTTPS回帰へ追加。本人分離、担当外／未参加イベント、現行行、既定OFFと保存済み状態、非GET/query、秘密列除外、旧URL、4幅×明暗の採用スタイル、失敗・不正DTO・遅延・401と正常空結果を検査する。ブラウザー状態4種は合成API値で分岐検証し、物理端末受入とは区別する。許可要求／購読取得・生成／SW登録を禁止する計測と非GET0、参照前後の設定一致を確認する。

集中実行は `SEM_FOCUSED_NOTIFICATIONS=1`。CI既定の全接続回帰・認証保護・保全復元・版照合は削らない。人工連続操作の読取枠は同じDB／鍵／Cookieを引き継ぐ別プロセス区画へ分け、製品制限を緩めない。最終固定候補の実行数・失敗と修正・CI/CD結果はPRと台帳へ記録する。
