# 本人プロフィール編集UIの接続段階

F08・U05〜U07・T02。既存の本人プロフィール参照へ、採用mock最終の編集モーダルを接続する。固定171資産・保存モデル・migrationは変更しない。

## 入力と現在本人の束縛

本人用 `#/profile` の編集ボタンだけを有効にする。本人IDのメンバー表示確認や別人のプロフィールには編集入口を出さない。開く直前に既存認可APIで現在本人の情報を再取得し、本人ID・own・世代・dialogの生存を確認する。401・不正DTO・取得失敗では旧入力を使わず、遅延した結果は画面移動／閉鎖後へ適用しない。

表示名、読み、対面呼称、絵文字のプレビュー、SNS行の追加／削除、有効プロフィール設問の入力を提供する。保存済みNOと未回答を区別し、名前／設問／回答をHTMLとして実行しない。既存の独自SNSサービス名は保持し、既定サービスへ無断変換しない。安全上限を超える既存値は黙って切り詰めず、編集を開けないと報告する。

項目の配置・入力上限・必須／任意・外部日本語JSONのヘルプを最終mockへ揃える。利用者作成の設問に固定ヘルプを機械的に付けない。現在の保存モデルにプロフィール設問のRequired列はなく、この段階で必須を推測生成しない。

## 取消と保存の境界

入力はdialogのメモリ内だけ。キャンセル・×・Escape・背景で未送信入力を破棄し、起点の本人編集ボタンへフォーカスを戻す。開き直しは現在の保存値から始める。Enterは暗黙保存／完了にしない。ウィンドウfocus／定期取得で開いている入力を勝手に上書きしない。

確定保存・画像アップロード／削除・QRは未接続。保存ボタンと画像ファイル選択を無効にし、未送信である説明を表示する。localStorage保存・成功トースト・模擬反映は入れない。画像の即時保存と通常の入力保存／取消を後続で独立させる。

読みの正規化やURL等の確定入力検証、現在認証・Origin／CSRF・版・操作ID・結果不明と再取得は保存契約の後続範囲。入力UIだけで保存や全UI完成、実機受入、実認証公開を完了扱いにしない。既定公開配置はdemoのまま、実volume・DB・鍵・秘密設定は未接触。

## 検証

合成HTTPSで現在本人の初期値、未回答／NO、停止設問の除外、文字列エスケープ、独自SNSサービス、追加／削除、絵文字、4方式取消、フォーカス保持／復帰、Enter、失敗・401・別人・不正値・遅延を検査する。入力と取消だけで保存要求がなく、参照値が不変であることを確認する。

同じデータの最終mockと320／390／768／1440px×明暗でdialog・アイコン・名前・読み・呼称・SNS・設問の主要スタイルと項目順・必須表示・YES／NO選択肢を比較する。低い画面は内部スクロールで操作できることを検査する。集中実行と全接続回帰は別に記録する。
