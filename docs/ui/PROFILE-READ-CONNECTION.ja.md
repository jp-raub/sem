# 固定プロフィールUIの参照接続

## 範囲

要件正本のF08・U04・U07・D04・N01に対応する実装段階。固定mock `9cf8b031258fa1c9afe9668f54e61f002c4bce17` の171資産・CSSは変更せず、全ラッパー適用後の本人、メンバー、コンパクトプロフィールへ参照専用DTOを接続する。旧main `812b2784212e9015ecbbce31280e48cb0bc65e84` の公開項目・登録参照契約を照合し、旧Razorや大きな保存サービスは戻さない。

- 共通メニューのプロフィール管理から本人カードへ、名簿／登録済み枠からコンパクト表示、そこから対象IDの詳細へ移動できる。表示名の一致で相手を推測せず、枠DTOへ現在のユーザーIDを加えて参照する。
- 読み・呼称・絵文字、資格情報を含まないHTTP(S)のSNS、有効なプロフィール設問と保存回答を表示。NO、未回答、空白を不必要に同一視しない。名前・設問・回答はHTMLとして挿入しない。
- 本人画面の編集とQR発行は未接続として無効化する。画像アップロード／削除、保存、QR生成、未ログイン共有は含めない。ダミーQRや架空の発行成功を出さない。
- 既定公開配置はdemo。明示実認証モードだけに接続し、実DB・鍵・私有設定は操作しない。全UI完成や公開実認証有効化の宣言ではない。

## 認可と最小投影

`GET /api/ui/profiles/{id}` と `/image` で、閲覧者の有効性・メール確認・現stamp・session失効と、対象の有効性・メール確認を同じSQLite読取snapshot内で再確認する。役割claimだけを権限として採用しない。匿名／失効は401、欠落／無効対象は同じ404、queryは400、非GETは405。no-storeと参照用resource policyを共通境界から使う。

メール・認証情報・行版・停止中プロフィール設問／回答・イベントの私的設問／回答・受付メモ・招待・QR資格情報を返さない。プロフィール設問とイベント設問は別テーブルの公開契約であり、混ぜない。SNSの不正スキーム・資格情報入りURLは除外する。不正な保存JSON等は固定422とし、元の秘密値をエラーへ含めない。

既存正規化PNGは毎回同じ認可を通した別入口で配信する。出力1MiB、寸法1〜512、PNG/IHDRと保存寸法の一致を確認する。削除済みの空画像を発行せず、画像の有無は保存寸法で最小投影する。完全な画像再デコード・変換や、新たな画像保存方式を実装したという意味ではない。

## 現在登録の表示

旧プロフィール登録参照の候補100件という境界を維持する。現在の演奏割当（有効な曲・イベント内パート定義）と観覧関係から候補を重複排除し、UTC瞬間として開催日時の新しい順・同時刻はID順で最大100件を選ぶ。時刻不正は表示しない。その後に**閲覧者**の現DB全体管理者／担当と実効フェーズで認可する。対象自身が非公開イベントへ所属していても、閲覧者の権限を増やさない。非公開で欠けた分を古い候補から補充しない。

現在の演奏がある場合は重複観覧を表示せず、曲と全パートをまとめる。削除済み曲・定義、登録履歴・受付履歴から参加を復活させない。これは全履歴でも、実際の出席／演奏の証明でもない。参照でDB／WAL・cache・監査・割当等を更新せず、77モデル・43 migrationを変更しない。

## 古い応答と表示の破棄

画面移動／ログアウト／pagehideで要求を中断し、世代を照合する。コンパクトを閉じた後の遅延応答で再表示せず、別人へ応答を転用しない。表示中のページ／コンパクトは7.5秒間隔で再読取し、非表示・重複要求を抑止する。401や読取失敗で古い本文・名簿・画像を残さない。閉じたダイアログ本文も消す。プロフィールデータ・メール・画像をWebStorageへ保存しない。既存のイベントタブ選択だけの保存は維持する。

## 検証の扱い

最終候補の合成DB37検査と実製品合成HTTPS188検査（クライアント例外0・外部通信0）で確認する。合成DBで公開投影・NO／null・対象無効化・閲覧者失効・候補100件先行・非公開と現権限・画像認可・DB／WAL不変を確認する。実製品HTTPS＋仮想認証器と固定mockへ同じ合成データを入れ、本人／メンバー／コンパクトの主要DOM・寸法・書体・配色、入力値の文字表示、詳細導線を比較する。本人／メンバー／コンパクトを4幅×ライト／ダークで比較する。全面pixel一致・全端末・物理認証器を保証しない。

初期の合成画像版0、JSON保存制約に抵触する負例は、製品の制約を弱めず正しいfixtureへ修正した。SQLiteが画像配列のAnyへ最適化した式を翻訳できない点は、画像有無の保存寸法投影へ修正した。本人カードの公開表示確認リンクの欠落も、同一データの高さ比較で検出して修正した。画面切替前の同じselectorを完了と見なしたテストは、本人カードの出現を待つよう修正した。失敗試行は成功へ流用せず、新規DBから最終候補を再検証する。

## CI失敗と比較待機の修正

初回head b66c592のCIは製品UI工程で失敗し、その試行を成功扱いにしない。診断注釈だけを追加した6557befのCIは成功した一方、同じ候補のローカル再実行ではコンパクト表示の配色比較が2回失敗した。合成値の比較結果では寸法・文字列は同じで、製品はlight、固定mockは直前のdarkだった。`emulateMedia`の完了後の50ms待機では、非同期のchange通知によるdata-mode反映を保証しないことを再現した。初回CIの詳細ログがないため、その失敗原因まで同一と断定しない。

比較の前提は、両ページのmatchMediaと実際のdata-modeが指定した明暗に一致するまで最大5秒待つ方式へ変更した。固定mock171資産・製品テーマ処理・188検査の比較項目・厳密一致は変更しない。修正後は新規合成DBからの188検査を3回連続で成功確認した。今後の失敗は安全なGitHubチェック注釈にも記録する。
