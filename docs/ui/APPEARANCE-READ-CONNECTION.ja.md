# 保存済み配色の参照適用

## 接続範囲

F12・U01・U06・T02・D04。固定mock171資産を変えず、明示実認証モードの初回表示・通常hash移動・再取得へ保存済み配色を接続する。これまでの実認証UIは固定green＋端末モードだけだった。

`GET /api/ui/appearance` は本人／サイト、`GET /api/ui/events/{id}/appearance` はこれに閲覧可能な対象イベントを加える。いずれも現DBの本人・stamp／session失効と対象認可を同一SQLite読取snapshotで検証する。クライアントの古いロールclaimでHiddenを許可しない。GET以外、query／本文による他ユーザー指定は提供しない。

## 継承と最小投影

配色とモードは**それぞれ独立**に個人→対象イベント→サイト→既定で解決する。nullは下位継承、mode 0は明示したsystem、1はlight、2はdark。個人systemを下位darkで上書きしない。影に隠れた下位層も含め、明示参照の欠損・不正色・不正modeは拒否し、勝手に別のテーマへ読み替えない。

DTOはactorId、eventId、palette、mode、必要な4色だけ。カタログ名・全カタログ・他人の設定・ThemeId・版・メール・認証情報は返さない。色は厳密な7文字 `#RRGGBB` とし、URL・CSS式・末尾改行を受け付けない。DB／WAL・cache・監査は書き換えない。

## 固定mockへの投影

- 固定mockの基本4色（green／blue／purple／amber）は、保存値が標準カタログそのものなら最終CSSのpaletteを使う。旧製品のCSSへ置き換えない。
- 追加6既定色・カスタム色・編集された基本色は、固定 `event-features.js` 最終版の4色からの計算と同じCSS変数に投影する。ライトのmuted／line／accent-soft等、ダークのaccent混色と背景継承も同じ。固定資産は変更しない。
- 端末モードのchangeでは現在の保存モードを再適用する。systemだけが端末へ追従し、明示light／darkは変えない。
- 初回の画面本文を描画する前に、現在世代・本人・対象に束縛した解決結果を適用する。前のイベントの色を読込完了後まで残さず、リロードを必要条件にしない。通信完了前の一瞬の既定配色の完全排除は保証しない。
- 色はメモリだけ。Web Storageへ本人設定・メール・認証情報を保存しない。

## 失敗・後続

遅延した別世代／別イベント／別本人の応答は捨てる。401・不正DTO・取得失敗・pagehide／ログアウトでは古い私的表示と適用状態を消し、失敗は既定の正常表示と混同しない。取得失敗は設定保存や再ログインを強いず、明示再試行で復帰できる。

この段階は**保存済み値の読取と適用**のみ。選択UI・プレビュー・適用保存・取消・テーマカタログ編集は後続。実volume／鍵／私有設定は未接触、既定公開配置はdemoのまま。

## 検証経路

`tests/Sem.Appearance.Checks` は合成DBで独立継承、10テーマ・カスタム、明示system、別人分離、下位の不正参照、DB／WAL不変と現認可を検査する。

`appearance-browser.cjs` は既存の合成HTTPS製品検証から実行する。実APIの既定・no-store・担当外拒否を確認した後、組合せは合成DTOで固定mockの全色トークンと比較する。DBから各色を変更するE2Eを11回繰り返す証拠とは区別する。通常hash移動・端末モード・遅延／失効・不正値・失敗再試行を検査し、既存UI回帰も維持する。

ローカルの配色診断だけなら、同じ製品／fixture DLL指定に `SEM_FOCUSED_APPEARANCE=1` を加える。出力は「配色集中HTTPS」として全接続回帰と明確に区別する。CIはこの変数を指定せず、既定の全接続経路を維持する。モック比較は端末設定変更後の最終renderを実行した確定状態で行い、同じhashへのgotoを新規取得と誤認しない。
