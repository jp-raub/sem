# 固定mockの本人アカウント参照接続

## 範囲と境界

要件F02・U02・U07・D04・N01に対応する参照段階。171固定資産は変更せず、独立した`ProductUI/account-view.js`を明示実認証モードだけで読み込む。通常の公開配置はdemoで、実volume・鍵・私有設定・SMTPは接続しない。

- `#/account/manage`は最終`management-navigation.js`のaccount-management-hub、メール区画・パスキー表を基準にする。
- `#/account/passkeys`は既存のキー入口として保持。`#/account/email`は採用入力寸法・最終ラベルと任意バッジを保ち、未接続を表示する。
- 共通メニューはプロフィールの後、ログアウトの前にアカウント管理を追加する。他の未接続メニューを動くように見せない。
- キー追加・削除・メール変更は無効。サンプルキー、確認済みへの模擬遷移、メール送信、最後のキー削除の認証迂回を作らない。参照実装はそれらのフローの完成を意味しない。

## HTTPとデータ

`GET /api/ui/account`だけを提供する。対象ユーザー指定を受け付けず、クエリ・GET本文等を拒否する。他人を指定するpathや書込操作を提供しない。既存のHTTPS・Host・現セッションmiddleware、no-store、読取レート制限を適用する。

SQLiteの同一read snapshotで現本人・Enabled・EmailConfirmed・security stamp・session失効を再確認する。現在のDBユーザーと標準Identityストアを使い、本人の`actorId`・`siteName`・`email`・キーの`name`/`createdAt`だけを返す。Credential ID、公開鍵、署名回数、transport、attestation、鍵バックアップ状態、認証証明、他人のメールを返さない。登録時刻が欠損ならnull、名称欠損なら空とし、UIは「記録なし」「名前未設定」で区別する。0件はサンプルで補充しない。

読取では最終利用・監査・DB／WAL・既存キー情報を更新しない。キーが別操作で削除された後の再取得は現在のストアに従う。返却量が極端に多い／不正なら固定422として、黙って一部を欠落させない。

## 表示・非同期保護

名前やメールはHTMLとして扱わない。DTOの許可キー・型とactorIdを現在の本人へ照合する。表示中は既存7.5秒の再取得へ含め、重複・非表示時の読取を抑える。取得失敗・401・アカウント不一致・画面移動・pagehideで古いメールとキーを消去し、遅延応答を新画面へ適用しない。メールやキーをWeb Storageへ保存しない。正常0件、取得失敗、未接続を分ける。

## 集中検証

- `tests/Sem.Account.Checks`: 標準ストア、本人／別本人、最小投影、日時欠損、DB／WAL不変、キー削除後の再取得、stamp・session・匿名・無効・未確認等の33検査。
- 実製品合成HTTPSでは既存188検査を維持し、APIの最小形・no-store・本人以外指定拒否・読取専用、共通メニュー、hub／旧入口、4幅×明暗の最終mock比較、メール入力寸法とラベル、文字エスケープ、遅延応答・401・503・別actor・0件と明示再試行を追加する。
- 任意バッジを含む最終DOMを実際の全ラッパー適用後に照合する。単体の元スクリプトだけを完成形とみなさない。寸法比較前は両ページのmatchMediaとdata-modeの実反映を待つ。

これは合成環境の参照接続であり、実認証公開の有効化・キー追加／削除の再認証・メール送信・物理端末の全確認ではない。

## 初回CIの比較前提修正

初回候補4335b19cのintegration-checksは成功したが、ブラウザー検査はメール入力ラベルのouterHTML参照でnullとなり停止した。固定mockは入力を生成した後、非同期の最終装飾でcompact-captionを追加する。入力の存在待ちだけでは最終ラッパー完了を保証しないため、両ページのcaptionが実際に存在するまで待ってから厳密比較する。ラベル・バッジのassertionを省略せず、171資産・製品処理も変更しない。初回CIの失敗を成功へ流用しない。
